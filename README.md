# ClaudeDock 控制面板

ClaudeDock 是一个面向 Windows 的桌面控制面板，用于在图形界面中同时管理多个项目的
真实 PowerShell 伪终端、项目级 Claude Code 模型/API 接入、会话上下文与常用斜杠命令，
并通过系统托盘查看后台状态。

## 当前版本重点（2.0.2 · 2026-07-29）

- 点击活动栏“对话”后，只要输入框当前可用且没有详情抽屉或设置弹窗占用焦点，就会在下一绘制帧
  自动聚焦独立对话输入框；再次点击“对话”收起左栏时也保持这一行为。
- 独立对话输入框不再使用浏览器默认焦点环。聚焦时由当前主题的强调色令牌驱动描边、底色和
  一次收敛式微光动效；Claude、Telegram、石墨和深海蓝分别显示自己的颜色与节奏，并继续遵守
  `prefers-reduced-motion`。
- “详细信息”抽屉改为紧凑的“说明 / 网络策略 / 运行状态 / 请求审计”结构，内容从顶部自然排列，
  不再把短文案和开关拉伸成不成比例的大块区域；联网控制收敛为紧凑开关，运行与审计各自带
  边界说明。
- “对话”左栏删除模型接入迁移提示，只保留从标题一直延伸到底部的完整对话历史；列表不再受
  248px 高度上限约束，模型接入继续统一从右上角齿轮弹窗打开。

## 2.0.1 版本重点（2026-07-29）

- 主题切换现在贯穿字体、动效、几何与配色四条轴，而不只是换色。样式表里通用的时长、缓动、
  圆角、行高、字距和字重阶梯全部由主题自有令牌派生：`--ease-standard` 指向主题的
  `--ease-enter`，`--dur-2` 指向 `--dur-micro`，`--r-md` 指向 `--r-theme-md`，行高与字距
  按固定比例从 `--lh-body` / `--ls-title` 推导。切到 Telegram，整个外壳的过渡变慢（0.12s →
  0.15s）、缓动换成它自己的长回弹、圆角收紧（12px → 8px）、行高收紧（24.1px → 21.2px）；
  切回 Claude 则恢复宽松节奏。标题、对话框标题与项目卡也开始使用主题的 display 字体，
  Claude 的 Source Serif 4 衬线标题因此可见，Telegram 保持单一 Open Sans。
- 独立对话输入框支持 Ctrl+V 直接粘贴图片与文件。剪贴板里的图片没有磁盘路径，因此走新的
  字节导入通道 `chat:import-attachment-bytes`，由主进程按同样的数量、体积和媒体类型上限
  校验后写入附件目录；同一次粘贴里混有路径文件和内存字节时两条通道并行处理。
- 修复独立对话连不上中转网关的问题。Claude Code 注入 `ANTHROPIC_API_KEY`，而多数中转站读
  `Authorization: Bearer`，此前对话客户端只发 `x-api-key`，导致项目能接入、对话接不上；
  现在两个头同时发送。
- 修复回复被截断导致的“降智”观感：流式 Anthropic 请求的 `max_tokens` 此前硬编码为 4096，
  会连思考一起截断，现在提升到 64000，并在网关拒绝时按 8192 降级重试。
- 模型接入表单从左栏移到「对话」右上角的齿轮弹窗：背景模糊、面板清晰，左栏只保留历史。
- 每个独立对话都可以像项目对话那样重命名，并带同样的打字机擦除/重打效果；重命名后的名字
  会被持久化的 `titleCustom` 标记保护，不再被首条用户消息派生的标题覆盖。

## 2.0.0 版本重点（2026-07-29）

- 终端主题现在从创建实例开始就由 ClaudeDock 接管：当前 xterm 调色板、后续新建终端、
  PSReadLine 24-bit 语法色和 Claude Code 自身的明暗主题保持一致。亮色主题不再出现黑底、
  黑边或低对比度 dim 文本。
- 窗口连续缩放和左右分隔条拖动改为 100ms 尾沿防抖；只有冷启动继续执行四帧有界测量。
  主进程无条件确认最终行列数，xterm 获得 Windows ConPTY build hint，避免重复重排造成的
  输出重影和重复行。
- 切模型、切权限模式与压缩重启期间，终端显示冻结快照、主题化 veil 和居中状态标签；底层
  xterm 仍继续消费 PTY 输出和权限徽标探测，操作结束后一次恢复，不丢输出也不改变面板尺寸。
- 独立对话升级为安全富文本：Markdown 由 token 树逐节点构造 DOM，不使用 `innerHTML`；
  支持标题、列表、表格、引用、链接、图片、KaTeX 公式、Shiki 语法高亮和代码复制。流式回复
  按动画帧合并，并只追加稳定 token 前缀，未闭合代码围栏不会先渲染成错误段落。
- 模型给出的 HTML 代码默认保持高亮文本，只有用户点击“运行此可视化”后才创建
  `sandbox="allow-scripts"` 且无同源权限的 Artifact iframe。内置 d3、Plotly、Mermaid 和
  KaTeX 可离线加载；“详细信息”抽屉显示完整网络请求、状态与可可靠取得的响应字节数，并提供
  持久化总断网开关和逐个停止入口。
- 独立对话支持 PNG/JPEG/GIF/WebP、PDF、CSV、TSV 和纯文本附件。文件由主进程校验并复制到
  `userData/claude/chat-attachments/`，历史 JSON 只保存 UUID 与元数据；图片以缩略图、
  文档以文件卡片显示。Anthropic 与 OpenAI 线格式分别序列化，1.x 纯字符串历史可透明读取。
- 四套主题开始表达不同人格，而不只是换色：Claude 使用 Inter 正文、Source Serif 4 标题、
  宽松行高与柔和圆角；Telegram 使用 Open Sans、紧凑行高、较小气泡圆角和自己的缓动；
  石墨与深海蓝保持中性工程风格。主题还控制按压、进退场、遮罩和 Artifact CSS 变量。

## 1.7.0 版本重点（2026-07-28）

- “项目与对话”的每条历史对话新增可见删除按钮，右键菜单也提供同一操作。删除前使用应用内
  对话框明确提示永久且不可恢复；若该 Claude conversation 正在运行，会先关闭对应终端，
  再按规范化项目路径与 UUID 删除精确的会话记录并刷新列表。
- “对话”已移到活动栏最上方，让“项目 / 接入”保持相邻。独立对话现在实时显示把输入草稿、
  历史消息和流式回复计入的上下文与输入/输出 Token；接口提供真实 usage 时显示精确值，
  否则明确标成估算值。工具栏提供“新对话”，接入表单提供与项目页一致的 1-token 连接测试。
- 独立对话历史会自动保存到本机，最多保留 50 个对话、每个 100 条消息；左栏可恢复或经
  应用内二次确认永久删除。它不启动 PowerShell，也不复用项目级 Claude Code 配置；支持
  Anthropic Messages 与 OpenAI Chat Completions 兼容接口，凭据仍只以 Windows 安全存储
  密文保存。
- 主题系统从“只给深色外壳换色”升级为两套明亮主题和两套深色主题。默认的“Claude 明亮”
  使用暖白纸面、陶土强调色和 Open Sans，“Telegram 明亮”提供冷白表面与蓝色交互层；
  两套深色主题继续保留。主题同时切换排版、表面层级、阴影、交互层、语义状态色、xterm
  与 Windows 原生标题栏。
- 按钮悬停不再上浮，改为描边与微光反馈，避免文字重采样闪烁；消息进场和选择反馈采用
  Telegram 风格的 200–300ms 快速减速曲线，并完整遵守 `prefers-reduced-motion`。
- 活动栏左下角新增常驻“设置”入口。全局设置首期按“总设置 / 接入”分类：总设置包含实际
  开机启动状态、主题、当前可用语言与应用版本；原“接入”页里的高级设置入口已移除，认证来源、
  网关发现、Router、cURL 和诊断工具整体迁移到“全局设置 → 接入”，没有复制第二套状态。
- 打开“接入”页时只展开上一次所选服务商所在的分类：官方、自定义及其他分类都遵循同一规则，
  其余分类默认折叠；离开页面后手动展开的临时状态不会污染下一次默认状态。
- “高级设置”新增“认证来源与密钥冲突”：默认让 ClaudeDock 保存的显式凭据成为该项目会话的
  唯一凭据，避免与 Claude Code 用户/项目设置里的 `apiKeyHelper` 同时生效；高级用户也可选择
  保留 helper。推荐模式只写运行期临时设置，不修改原 Claude Code 配置文件。
- PowerShell / Claude Code 输出区获得鼠标或键盘焦点时显示克制的主题色描边与微光，明确反馈
  原始终端已接管输入；减少动态效果偏好仍会关闭过渡。
- 终端底栏的“连接待测试”改成真按钮：点击后直接用当前项目已保存的接入配置开始真实连接测试，
  不再自动跳到“接入”页；按钮进入转圈的等待态并禁止重复点击，测试结束后自动恢复成连接正常/
  需确认/异常。“测试并接入”也改为由同一个测试生命周期统一恢复，不会在成功保存后持续转圈。
- 底栏“模型”可点击，弹出与整体样式一致的列表，来源是当前接入配置和该项目的接入历史
  （中转、本地、国内、国外、官方 API 与官方账号都在其中）。同一端点的模型在运行中的对话里
  即时切换；换了接口地址或凭据的条目会先确认，再压缩上下文、重启会话并用 `--continue`
  接回原对话。
- 运行中切换模型不再把 `/model <模型>` 与回车一次性写进 Claude Code：正文与回车按安全间隔
  分两次提交，同一会话的应用内斜杠命令排队执行，避免命令停在输入框或快速操作时字节交错。
  切换成功、失败或异常都会立即恢复模型按钮，列表当前项以本次会话实际选择为准。
- 底栏新增“模式”，列出 Claude Code 的全部权限模式：手动确认、自动接受编辑、计划模式、
  自动选择、完全允许、仅预批准。终端和输入框里按 `Shift+Tab` 都能切换，PowerShell 里的
  模式徽标与底栏显示实时同步。
- 点击模式列表时先主动读取一次 xterm 中的真实徽标，确认当前模式后才逐次发送 `Shift+Tab`；
  每次按键都要等屏幕差量应用完成并再次回读，命中目标才停。若当前在选择器、确认框等画面而
  读不到徽标，ClaudeDock 不会发送按键；若循环回到已访问模式，也会立即停止并提示目标不可用，
  避免 `auto` 等可选模式缺席时继续盲按而切歪。
- 工作台新增“允许「完全允许」模式”开关，默认开启：启动时预置但不激活，之后可用 `Shift+Tab`
  或底栏切入。关掉后需要重新启动会话，启动命令也不再带
  `--allow-dangerously-skip-permissions`。
- “仅预批准”不在快捷键循环里，只能在启动时设定，选择后走与跨端点换模型完全相同的
  “压缩 → 重启 → `--continue`”流程。

## 更早版本重点（2026-07-27）

- “接入”页改为“环境准备 → 选择服务商 → 填写凭据与模型 → 测试并接入”三步主流程。
  Anthropic、DeepSeek、GLM、Kimi、通义千问、MiniMax、豆包、MiMo、StepFun、
  SiliconFlow、OpenRouter 和 Ollama 等入口由同一份服务商目录预填官方兼容基址、认证方式、
  主模型与快速模型；自定义 Anthropic、Router 和 cURL 路径完整保留在高级方式中。
- 服务商类别都可点击标题展开或收起，并带箭头与过渡效果；服务商卡片根据侧栏实际宽度自动
  切换一、二、三列。再次点击已选服务商会取消选择，此时后续配置与测试步骤整体收起，页面只
  保留服务商选择、高级设置入口和可复用的历史配置。
- “高级设置”改为主题自适应的模态窗口，集中承载网关、cURL、Router 和诊断工具，并提供
  “完成”“取消”与 `Esc` 关闭；取消会恢复本次打开窗口前的未保存输入，已经执行的安装、卸载、
  启停或 Router Provider 保存仍立即生效。
- “选择历史配置”保留在接入主流程中，位置固定在高级设置入口与模型配置之间；每条直接展示
  曾填写的接口/网关、主模型、快速模型、认证和凭据状态，点击即可恢复全部保存参数。
- 连接测试通过后才自动保存；401/403、404、400/422、超时、网络错误和非标准 Anthropic
  响应会生成可点击的修复动作。Kimi 开放平台/Kimi Code 密钥不通用、SiliconFlow 使用
  `x-api-key` 等服务商差异会在选择时直接提示。
- 标题栏右上角新增统一刷新图标：首屏完成后会在后台检查 Claude Code、Router 与插件市场，
  平时不再常驻“更新”按钮；只有确认存在新版时才显示对应更新入口，未安装的软件仍显示安装
  入口。点击刷新图标会强制刷新软件元数据与插件市场。
- 修复窄侧栏下插件市场的最小宽度与遮挡：长插件名、仓库地址、市场表单和多按钮操作区都能
  在容器内换行/收缩，820px 最小窗口不再横向溢出。
- 修复窗口偶发进入“看得见但点不动”的状态：分隔条拖拽即使被失焦、托盘隐藏或系统取消打断，
  也会主动释放鼠标捕获；窗口恢复后会重新校准终端布局。新建/切换对话时，输入框会等到对应
  PowerShell 真正进入运行态再获得焦点，不再依赖固定毫秒延时。
- 修复点击“真实测试端点、密钥和模型”时接入页与 PowerShell 短暂无响应：安装检测、Router
  状态、网关扫描和软件更新现在共用两个受控后台任务槽，同类请求合并，用户发起的真实测试
  优先于尚未开始的自动刷新；测试卡会显示后台状态，其他界面仍可继续使用。
- 启动后不再凭空出现一个以 Windows 用户名命名的项目：没有打开项目时工作区就是空的，
  界面显示引导态，等用户点击最近项目或添加文件夹。
- “接入”页新增接入历史记录：每次保存都会留一条，与上一条完全相同则不新增；点击一键恢复
  当时的全部配置，右键菜单或记录右侧的 `×` 都可以删除。凭据仍只存在 Windows 安全存储里，
  历史文件本身不含明文。
- 输入框把快捷键说明改成占位文字（开始输入即消失），发送按钮撑满右侧整列；发送时提示词
  以气泡上浮的方式离开输入框。
- 终端不再有一圈黑边，输出区背景跟随所选主题；点击发送会真正提交给 Claude Code，而不是
  只把文字粘进它的输入框。
- 修复 `Ctrl+C` 等场景下两屏叠在一起的重绘错位：PTY 采纳的尺寸会回传给渲染层，xterm 与
  ConPTY 始终在同一网格上。
- 面向公开用户的环境准备与接入向导：检测 Claude Code/Router，并提供官方源、npm 官方源
  与 npmmirror 国内镜像的一键安装或更新。
- Router 可识别桌面版、npm 版和混合安装；用户可停止并彻底卸载旧安装（连同全部配置数据），
  再切换来源安装新版；npm prefix 之外的安装目录也能清除。
- 插件市场直接读取 Claude CLI 的官方目录，支持安装、启停、卸载、刷新市场与批量更新；单个
  插件与“更新全部”只在目录确认存在更新后出现。
- 工具内的按钮、状态、错误与插件能力说明统一使用中文；PowerShell 原始输出、产品名、命令、
  网址和插件 ID 等必须保持准确的技术标识不做翻译。
- Windows 安装向导固定使用简体中文。
- 插件 ID 保留官方名称，英文说明通过本地规则生成中文能力说明，界面不再显示英文原文。
- 统一全部滚动区域的样式；左侧控制栏与右侧工作台都可拖动调整宽度并记住设置。再次点击当前
  活动栏按钮会收起左侧控制栏，业务入口与底部设置仍保持可见，再次点击任一入口即可展开对应页。
- 820px 起的窄窗口和 640px 起的低高度都有独立响应式布局，控件空间不足时换行或收起次要
  信息；插件名、市场地址、表单和操作按钮不会再用隐含最小宽度撑破侧栏。
- 工作台状态下沉到终端底栏，直接显示连接健康、上下文占用与运行模型；快捷键说明独立成页。
- 终端区分为「输出区 + 输入框」：提示词写在输出区下方的独立多行输入框里，因此 `Ctrl+A`
  全选、`Shift+←/→` 逐字选择、鼠标拖选、`Ctrl+Z` 撤销和中文 IME 都是浏览器原生行为；
  `Enter` 发送、`Shift+Enter` 换行（多行提示词作为一条命令进入 PowerShell）、`↑/↓` 翻本地
  历史。输出区仍可直接点进去打字，供 Claude Code 自身的 TUI 使用。
- 快捷键说明是输入框的占位文字，开始输入即消失；发送按钮撑满输入框右侧整列。发送时提示词
  会以气泡上浮的方式离开输入框，开启「减少动态效果」时不播放该动画。
- PowerShell 终端提供 UTF-8 中文输入、标准复制/粘贴、跨行退格和右键菜单；输出经 WebGL
  渲染器绘制，并在主进程与渲染层两侧合并写入，大量输出时不影响输入手感。
- 删除、清空和重启等确认操作统一使用应用内模态框，不调用 Electron/Chromium 的原生
  `alert` / `confirm`；关闭模态框后恢复原焦点，窗口从托盘或其他应用切回时会重新同步会话
  状态，避免终端中文 IME 与独立输入框一起失去焦点或停留在错误的禁用状态。
- 工具栏可切换四套明暗主题，主题驱动整个外壳——标题栏、活动栏、侧栏、工具栏、底栏、卡片与
  原生窗口边框一起换色，终端底色外不会残留深色圈层；所选主题会被记住，冷启动即为正确配色。
  映射和 PSReadLine 调整仅在应用终端内生效。
  xterm 的 Unicode 11 宽字符组件按其要求启用提议 API，避免启动时出现
  `allowProposedApi` 错误。

视觉与交互约束详见 [design.md](design.md)。

## 功能边界

- 每个项目拥有独立的 Windows PowerShell/ConPTY 会话，可同时在后台运行。
- 冷启动和关闭最后一个对话之后，工作区是真正的空状态：会话总是属于用户自己选的文件夹，
  不会为了填满界面而在用户目录里起一个 PowerShell。
- 项目列表支持添加、切换和关闭项目；终端输出与滚动缓冲在项目切换后仍会保留。
- 将文件夹拖入窗口或使用目录选择器即可添加项目；重复添加同一路径会切回已有会话。
- 系统目录选择器只使用仍然存在的活动目录作为初始位置；目录失效时回退到用户目录，Windows
  父窗口句柄异常时自动无父窗口重试，并区分“选择器启动失败”和“添加项目失败”。
- 关闭主窗口后驻留系统托盘，可从托盘恢复、切换/添加项目或控制当前终端。
- “对话”是独立于项目终端的通用模型聊天页，配置保存在
  `userData/claude/chat-profile.json`；支持 Anthropic Messages 与 OpenAI Chat Completions
  兼容接口。消息历史以 version 2 明文 JSON 保存在 `userData/claude/chat-history.json`，
  最多保留最近 50 个对话、每个 100 条消息；可逐条永久删除。附件正文独立存放，历史只记录
  引用。输入草稿会实时计入估算上下文，接口返回 usage 后改用供应商给出的精确 Token。
- 左下角“设置”统一承载应用级设置；开机启动即时写入 Windows 登录项，主题与终端工具栏
  使用同一配置，当前版本只提供简体中文。高级接入工具位于“设置 → 接入”。
- 每个项目可以独立选择 Anthropic 官方接入、Anthropic Messages API 兼容服务或本地
  模型转换器。带 `/v1/chat/completions` 的 OpenAI 格式地址不能直接填给 Claude Code；
  服务商若另行提供 `/v1/messages` 则可以直连。DeepSeek 官方现已提供
  `https://api.deepseek.com/anthropic` 直连接口。
- 服务商目录是预设、认证方式、主/快速模型、控制台/文档链接和外链白名单的单一事实来源。
  切换服务商会清空未保存凭据和旧测试结果，避免把上一家服务商的密钥误发给下一家；重新打开
  “接入”页只展开上次选择所在分类。
- “接入”页自动发现 Claude Code Router（默认模型接口 `3456`、管理页 `3458`）、
  LiteLLM（常用端口 `4000`）、当前项目保存的本机地址，以及现有 Claude Code
  用户/项目设置；检测只回传地址和“是否有凭据”，不回传凭据内容。
- 可粘贴服务商提供的 cURL，自动识别 OpenAI/Anthropic 协议、接口、模型和认证头，并给出
  “可直连”或“先配置本地转换器”的明确下一步。
- “接入”页在服务商选择与模型配置之间保留每个项目最近 20 条历史配置。保存时如果所填内容与
  最近一条完全一致就不新增记录；网关运行状态只随记录一起显示，不参与判重，避免网关反复
  启停刷出一堆几乎一样的条目。卡片显示接口/网关、主模型和快速模型，点击一键恢复当时的
  接入配置（含安全存储中的密钥），右键菜单或记录右侧的 `×` 删除单条。
- 可在“接入”页一键获取 Claude Code Router 官方 Windows 安装程序、启动/停止模型网关、
  通过 npm 或 npmmirror 安装、卸载/替换旧版、打开完整管理页，并可视化新增、编辑、删除
  Provider。OpenAI cURL 可一键写入 Router，同时把 Router 路由接入当前 ClaudeDock 项目。
- CCR 管理服务已运行但 Provider 为空时，不再只显示 `No available models`：界面会解释
  当前项目是否受影响、禁止无意义的重复启动，并提供“用当前项目配置一键修复”或手动添加
  第一个 Provider。自动修复只在远程 Anthropic 直连和 API Key 已安全保存时可用。
- CCR 的 `better-sqlite3` 若被 Electron 内置 Node 误加载，界面会把
  `NODE_MODULE_VERSION` 报错解释为运行时不匹配，并提供“修复运行环境并重启”。修复只会
  用 CCR 安装时配套的系统 `node.exe` 重启管理服务，不重编译数据库、不修改 Provider，
  也不触碰 Codex。
- 可按 Claude 官方建议主动发送最多 1 个输出 token 的 `/v1/messages` 测试，分别显示
  端点、身份认证和模型响应结果；测试在受控后台队列运行并优先于待执行的自动刷新，响应正文
  最多读取 64 KiB。成功保存、测试失败和异常都会恢复“测试并接入”按钮；后台自动检测不会
  发起付费模型请求。
- “会话”页持续显示当前路由健康状态：使用本机 Router 时会在启动前确认 `3456` 网关与
  Provider 是否就绪；Claude Code 真实对话若返回 ConnectionRefused、认证、端点或模型
  错误，会立即显示红色提示并引导回“接入”页。
- Claude 工作台提供新建、继续最近和选择历史三种会话入口，并把 `/context`、`/usage`、
  `/model`、`/permissions`、`/compact`、`/theme` 等常用斜杠命令变成可点击操作。
- 新对话先显示“对话 1 / 对话 2”等临时名称；Claude Code 根据首条提示词生成标题后，
  ClaudeDock 会通过官方 `statusLine.session_name` 自动同步到左侧列表、终端标题和工作台范围，
  并以“擦除旧名、打字机输入新名”的动画原位更新（系统开启减少动态效果时直接替换）。
  这不会额外发送一条 ClaudeDock 提示词；手动重命名立即生效且仍会覆盖自动标题。
- 项目列表按“文件夹 → 当前对话 → 历史对话”折叠展示。历史对话完整列出并在文件夹内独立
  滚动，运行中对话固定在上方不随滚动移动；折叠开关只收起历史对话区，正在进行的对话
  始终可见，所以使用中的项目也可以收起。恢复历史仍通过 Claude Code 官方
  `--resume <session-id>`；运行中和历史对话均可重命名，历史项右键写入 Claude 的
  `custom-title` 元数据。历史项的 `×` 与右键“删除历史对话”都会先二次确认，再只删除该项目
  下经 UUID 校验的目标会话；工作台不再重复显示同一份历史列表。
- 通过 Claude Code 官方 `statusLine` 数据实时显示上下文窗口、输入/输出 token、会话估算
  费用、持续时间、模型和会话 ID；不解析易变的终端绘制文本。
- 终端底栏无需展开面板即可查看连接健康、上下文占用和模型；右键菜单提供复制、粘贴、
  全选和清屏，`Ctrl+C` 在有选区时复制、无选区时保持 PowerShell 中断语义。输出区聚焦时
  出现主题色微光，提示接下来的按键将直接进入 PowerShell / Claude Code。
- 底栏的连接、模型和模式三处都可点击：连接使用已保存配置在当前界面直接开始真实测试并显示
  等待态，不切换左栏页面；模型与模式弹出浮层列表，宽窗口显示、900px 以下随底栏一起收起。
- 模型切换分两条路径。同一接口地址、预设、认证方式和 helper 策略的模型走运行中的 `/model`，
  对话不中断；命令正文与提交回车分两次写入，并按会话串行化，避免 Claude Code 把整块输入
  识别为粘贴后吞掉回车。切换按钮在操作结束时直接解除禁用，不依赖后续状态刷新；
  其余条目需要更换环境变量，只能重启 PTY，因此会先确认再压缩上下文、重启并 `--continue`。
  被点击的条目会在主进程重新生成列表核对一遍，模型标识还要再过一次命名校验才写进终端。
- 权限模式的真值来自 Claude Code 自己重绘的模式徽标，`statusLine` 数据里没有这一项。
  Claude Code 会只输出变化的终端单元格，因此 ClaudeDock 用输出修订号确保 xterm 已合成完
  待处理差量，再扫描完整活动缓冲区并回报徽标。底栏切换在首次按键前和每次按键后都主动取样；
  读不到可靠徽标就不发键，检测到模式循环则停止，同一会话的并发点击也会被拒绝。
- `bypassPermissions`（完全允许）无法在未预置的会话里进入，这是 Claude Code 的限制。
  ClaudeDock 默认在启动时用 `--allow-dangerously-skip-permissions` 把它加进循环但不激活，
  可在工作台按项目关闭。`dontAsk`（仅预批准）永远不在循环内，只能在启动时设定。
- 插件页兼容原生 Claude 可执行文件与 npm 生成的 `.cmd/.ps1` 启动器；插件目录及市场刷新
  不依赖是否打开了项目。插件包 ID 不翻译，插件能力说明只显示中文版本；更新入口仅在后台
  或用户主动刷新确认有新版后显示。
- `claude plugin list --json` 的已装条目只带 `id`（没有 `name`/`description`，`version` 可能是
  `unknown`），并且已装插件会从 `available` 列表里剔除。ClaudeDock 用 `id` 反推包名与市场名、
  把 `unknown` 视为“版本未知”而不显示 `vunknown`，再用市场清单补齐中文说明，因此已安装的
  插件（如 frontend-design）在“已安装”页可见且不会误报可更新。
- 模型/API 路由只注入 ClaudeDock 为当前项目启动的进程，不修改 Codex、Claude Code
  全局配置或 Windows 系统级 API 路由；启动时会用更高优先级的临时设置覆盖用户配置中
  遗留的 CCR/Claude 路由别名，避免“测试直连成功、真实会话却回到已停止的 3456”。
- 不劫持任意已经打开的外部 PowerShell 窗口；应用创建并接管自己的 ConPTY 会话。

## 开发环境

- Windows 10 1809 或更高版本
- Node.js 24 或更高版本
- npm 11 或更高版本
- Claude Code 2.1.197 或更高版本（ClaudeDock 受保护启动的最低版本）

安装依赖并启动开发模式：

```powershell
npm install
npm run dev
```

常用命令：

```powershell
npm run lint
npm run format:check
npm run typecheck
npm test
npm run test:conpty
npm run test:layout
npm run test:visual
npm run build
npm run dist
```

`npm run test:layout` 会在隐藏的 Electron 窗口中检查 820×640、900×640 和 1180×760，
覆盖项目、对话、接入、插件四个分组、工作台三页、收起的左栏、全局设置两个分类，以及富文本
长内容、附件和 Artifact 抽屉压力态；共运行 42 个场景。若交互组件被透明层挡住、彼此重叠或
关键容器横向溢出则失败。
`npm run test:visual` 除保留插件页、接入向导、历史配置、全局设置、连接测试、终端聚焦态、
独立对话详情抽屉和重命名弹窗的回归图外，还生成 `claude`、`telegram`、`graphite`、
`midnight` 四主题乘以富文本对话、终端和终端遮罩三种状态的 12 张矩阵图；富文本对话矩阵会
聚焦输入框，以同时核对四主题的焦点颜色与动效终态。图片统一写入 `dist/visual-qa/`。
`npm run test:conpty` 使用一次性用户目录启动真实 PowerShell ConPTY，在 820→1400→900→
1280→1180px 间往返缩放并把最终终端截图写到
`dist/visual-qa/conpty-resize-live.png`；它只在 Windows 上运行，不会读取或修改日常用户数据。

`npm run dist` 在 `outputs/` 完成 Windows x64 打包，最终安装程序固定为
`outputs/ClaudeDock-Setup-<version>-x64.exe`。后续安装包、校验元数据和解包产物均只放在该
本地输出目录，不再复制到项目根目录。

每轮完成并验证的项目修改都要更新版本：不兼容或架构级变更升主版本，有明确发布价值的成组/
重大新功能升次版本，小功能优化、修复、文档、构建或维护改动升修订版本。随后必须运行
`npm run dist`，将对应版本的安装程序、blockmap、`latest.yml` 与 `win-unpacked/` 生成到
`outputs/`。

## 日常使用

标题栏右上角的刷新图标是统一更新检查入口。页面首次完成加载后也会自动在后台执行同样的
检查；没有发现更新时，Claude Code、Router 和插件区不会显示突兀的更新按钮。

1. 启动 ClaudeDock 后不会自动打开任何项目：界面停在引导态，等你从左侧点击最近打开过的项目，
   或添加一个新的项目文件夹。
2. 把项目文件夹拖到窗口任意位置，或点击虚线“＋ 添加项目”区域；应用会为它新建独立会话，不会停止
   已经运行的其他项目。
3. 在左侧项目列表切换当前项目；点击项目行右侧的关闭按钮会终止并移除该项目会话。
4. 点击左侧“接入”。如果 Claude Code 未安装、版本过旧或位于受阻止版本范围，先在环境卡完成
   安装或更新；环境达到受保护启动要求后，该卡自动收起。
5. 在第一步选择密钥所属服务商。目录会自动填好真实 Anthropic 兼容基址、认证方式、主模型和
   快速模型；Kimi 开放平台与 Kimi Code 会员必须按密钥来源分别选择。需要自定义地址、
   本地 Router 或 cURL 时，选择“高级方式”中的对应入口，功能没有被移除。每个类别标题都能
   展开/收起；再次打开页面时只展开上一次选择所在类别。再次点击当前服务商会回到未选择状态，
   后续表单随之收起。
6. 点击活动栏左下角“设置”，切换到“接入”，在全局设置窗口中调整认证来源，或使用自动发现、
   手动配置、
   Router 管理、cURL 识别、转换器说明与术语解释。显式 API Key / Token 默认选择
   “只使用 ClaudeDock 保存的凭据”；只有确实需要 Claude Code 自己的 `apiKeyHelper` 时才改为
   “保留”。完成后点“完成”，需要放弃未保存输入时点
   “取消”或按 `Esc`。如果服务商给了一段 cURL，选择“粘贴 cURL”后直接粘入：
   - 识别为 **Anthropic `/v1/messages`**：点击“自动填入可直连配置”。
   - 识别为 **OpenAI `/v1/chat/completions`**：如果已安装 Router，可点击
     “一键写入 Router 并接入当前项目”；应用会新增或更新 Provider、设为首选，并把
     `provider/model` 路由保存为当前项目的 ClaudeDock 接入。
   - cURL 中的 Bearer 上游密钥交给 Router；如果 Router 自己启用了访问保护，
     ClaudeDock 需要填写的是另一把 Router 访问密钥，二者不要混用。
     “接入”页的“选择历史配置”会直接列出曾填写的接口/网关、主模型和快速模型；需要复用时
     先点击该记录恢复全部参数，再继续模型配置。
7. 选择模型并填写凭据，点击“测试并接入”。测试最多请求 1 个输出 token，可能产生极少量
   费用；只有端点、认证和模型三项全部通过才自动保存。失败卡会解释原因并提供切换认证、
   打开服务商控制台/文档、改用快速模型、安装/启动 Router、重试或返回选择服务商等操作。
   “跳过测试并保存”保留给官方登录、离线配置或已明确接受风险的高级用户。
8. 没有 Router 时，在“安装来源”选择官方 GitHub 安装包、npm 官方源或 npmmirror，点击
   “一键安装”。GitHub 安装包会核对 Release 声明的文件大小与 SHA-256；npm 镜像只对
   本次命令生效，不改全局 registry。已有 Router 可点击“彻底卸载并清除数据”，会删除路由器
   程序、`%APPDATA%\claude-code-router` 下的全部 Provider 配置与上游密钥，状态回到“尚未
   安装”，随后即可换一个安装来源重新安装。该操作不可恢复，也不会触碰 `~/.claude` 下
   Claude Code 与 Codex 自己的配置。
9. “Provider 配置”支持 OpenAI Chat Completions、OpenAI Responses 和 Anthropic
   Messages 三种上游。可逐项编辑地址、模型和密钥，也可只点“用于当前项目”复用已保存
   的上游凭据。
   - 如果显示“还没有配置 Provider 和模型”，先看黄色“解决办法”卡片。
   - 当前项目已有测试通过的远程 Anthropic + API Key 时，点击“一键修复”会在主进程复用
     Windows 安全存储中的密钥，创建 Provider、启动 `3456` 并切换当前项目。
   - Bearer、无认证或当前项目本来就指向 `3456` 时，点击“手动添加第一个 Provider”，
     依次填写协议、接口、模型和上游密钥，保存后再启动 Router。
   - 如果出现 `better_sqlite3.node`、`NODE_MODULE_VERSION` 或“compiled against a
     different Node.js version”，点击“修复运行环境并重启”。这不是数据库损坏，也不需要
     手工运行 `npm rebuild`。
10. 保存成功后配置会进入“选择历史配置”，下次点一下即可整套恢复；不需要的记录可以右键或用
    记录右侧的 `×` 删除。API 凭据通过 Windows 安全存储加密，界面不会回读明文。
11. 左侧快捷操作可直接“新建安全会话”；工作台“会话”页还可继续最近会话或打开 Claude
    的历史选择器。启动会重建当前项目
    的 PowerShell，以便只通过子进程环境注入路由和密钥，因此会终止该终端中原有的进程。
12. 提示词写在终端输出区下方的输入框里，`Enter` 发送、`Shift+Enter` 换行、`↑/↓` 翻历史；
    Claude 响应后，终端底栏与“会话”页实时显示当前上下文；“命令”页执行白名单斜杠命令，
    “快捷键”页说明终端映射。终端顶部的主题选择会改变整个应用外壳的配色，命令页的 `/theme`
    打开 Claude Code 自身主题选择。Claude Code 完成首条提示词的后台命名后，左侧临时名称会
    自动替换为主题标题；也可随时右键手动重命名。`/clear` 会开启空上下文的新会话，执行前会
    二次确认。
13. 底栏左侧的连接按钮可以随时用当前项目已保存的配置重跑真实连接测试：点击后留在当前界面，
    按钮进入等待态且不可重复点击。底栏中间的“模型”弹出可切换的模型列表，同端点直接切、
    跨端点确认后压缩并重启；右边的“模式”列出全部权限模式，也可以在终端或输入框里按
    `Shift+Tab` 切换，PowerShell 里的徽标与底栏显示保持一致。想使用“完全允许”时，需要工作台的
    “允许「完全允许」模式”开关处于开启状态（默认开启），首次进入时 Claude Code 会弹一次
    自己的免责确认。
14. 点击窗口关闭按钮只会隐藏面板，所有会话继续在后台运行；右键系统托盘图标可以恢复
    窗口、切换/添加项目、控制当前终端或彻底退出。

需要通用模型聊天时，点击活动栏最上方的“对话”，焦点会自动进入消息输入框；独立协议、接口、
模型和凭据从右上角齿轮弹窗填写，可以先点“测试连接”验证当前草稿，再保存并发送。左侧整栏
只显示对话历史。这里的模型与项目“接入”可以完全不同；
工具栏会随输入和流式回复更新上下文/Token，“停止”只中断当前生成，“新对话”开启空白记录，
旧记录仍在左侧历史中，可恢复或永久删除，不影响任何项目或 Claude Code session。回形针或
拖放可添加图片、PDF 和文本/表格文件；模型回复会渲染 Markdown、公式与代码。HTML 代码要由
用户点击“运行此可视化”才会进入隔离 Artifact；右上角“详细信息”可审计联网并立即断网。
全局主题、开机启动和版本信息位于左下角“设置 → 总设置”。

安装时可自行选择 `D:\ClaudeDock` 等目标路径，并可在“安装选项”页面勾选或取消
“在桌面创建快捷方式”（默认勾选）。

## 安全与限制

- 界面只加载项目自带的本地内容，关闭 Node.js 集成并启用上下文隔离和沙箱。
- 用户在终端中输入的命令拥有当前 Windows 用户的权限，应用不会替用户审查命令。
- ClaudeDock 不把密钥写入项目、命令行或终端历史；保存的凭据使用 Electron
  `safeStorage`（Windows DPAPI）加密。受保护启动结束后会从 PowerShell 环境清理所有
  Claude 路由和凭据变量。
- 接入历史保存在 `userData/claude/connection-history.json`（权限 `0600`，临时文件加重命名
  写入），其中的凭据同样只以 `safeStorage` 密文存放，文件本身不含明文密钥。安全存储不可用
  时该条记录恢复出来就是“没有凭据”，而不是回落成明文。每个项目最多 20 条，超出丢弃最旧的。
- 独立对话配置保存在 `userData/claude/chat-profile.json`，凭据同样只存
  `safeStorage` 密文；renderer 只能看到“是否已配置”。模型请求由主进程发出，远程地址必须
  使用 HTTPS（本机回环可使用 HTTP）。
- 独立对话正文与 Token 快照以明文写入 `userData/claude/chat-history.json`（权限 `0600`，
  临时文件加重命名写入）；这是本机可恢复历史，不是加密保险箱。每次发送及生成结束都会更新，
  最多保留最近 50 个对话、每个 100 条消息。共享 Windows 账户或设备时应在历史列表中删除
  敏感对话；删除不可撤销。
- 独立对话附件复制到 `userData/claude/chat-attachments/<uuid>/`；图片预览是主进程缩小后的
  data URL，完整附件字节不会为预览跨 IPC。删除或裁剪历史会回收不再引用的附件。同一消息
  草稿跨多次/并发导入累计最多 10 个、32 MiB，并在发送前由主进程再次校验；不支持目录、
  符号链接和未列入白名单的扩展名。
- Markdown 原始 HTML 永远不会直接注入宿主 DOM；外链经主进程协议校验后交给系统浏览器，
  远程图片也不会在消息出现时自动加载或静默外发。
  Artifact 是显式执行边界：iframe 没有 `allow-same-origin`，也不能访问宿主 preload、
  cookie 或 localStorage。主进程把 Artifact 绑定到 `WebContents + frameTreeNodeId` 稳定身份，
  阻止 iframe 导航逃离自定义协议，并按该身份归因默认 session 中的外部请求；
  Chromium 未提供可靠响应体长度时界面明确显示“字节数未知”，不把 `Content-Length` 猜成
  实际下载量。
- 历史文件只在确实不存在时视为空；JSON 损坏、权限或读取错误会保留
  `chat-history.json.corrupt.bak` 并停止覆盖历史和附件回收，在界面报告错误，不把损坏误当
  成“用户清空了历史”。
- 第三方接入固定 `ANTHROPIC_BASE_URL` 与主/小模型别名，同时关闭遥测、错误上报、反馈、
  调查问卷以及 WebFetch 的 Anthropic 域名预检；这能阻断已知的非必要 Anthropic 流量，
  但不能替用户审计第三方网关，也不能证明网关没有在服务端替换模型。
- Claude Code 会按优先级合并用户、项目和命令行设置。ClaudeDock 的临时 settings 会明确
  覆盖 `ANTHROPIC_API_BASE_URL`、`CLAUDE_AGENT_API_BASE_URL`、`CCR_CLAUDE_CODE_MODEL`
  等第三方 Router 遗留别名；使用推荐的“ClaudeDock 单一凭据”策略时还会用空覆盖停用继承的
  `apiKeyHelper`，避免与显式 `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN` 并存。临时文件只含
  地址、模型和空覆盖值，不含 API 凭据，也不修改用户或项目设置。
- ClaudeDock 拒绝受保护启动已披露含隐藏地区/代理检测逻辑的 Claude Code
  2.1.91–2.1.196。Anthropic 当前仍不向中国大陆/香港及受不支持地区控制的实体提供官方
  服务；ClaudeDock 不会伪造位置、绕过地区限制或保证官方账号可用。
- 经中转时，项目代码、提示词和输出会经过该网关。只使用有明确数据处理、日志和模型路由
  说明的服务，不要把生产代码交给来源不明的低价中转。
- 自动发现每 6 秒检查已知本机端口，只发送不带凭据的连通性/模型列表探测；它不会扫描全部
  端口，也不会自动调用远程模型。只有用户点击“真实测试”后才会向当前表单地址发送
  1-token 请求。
- 首屏后台更新检查会读取受信任 registry 的软件版本并调用 Claude CLI 刷新插件市场；它不
  发送模型请求。标题栏刷新图标会重复该检查，只有确认存在更新后才显示更新操作。
- 会话启动前只对当前项目确实指向的本机 Router 做阻断检查；其他远程直连项目不会因为
  本机 CCR 故障被错误阻止。运行中只识别 Claude Code 明确输出的 API Error 类错误，并将
  常见原因映射为中文；未识别的英文错误不会直接进入界面，原始终端输出仍原样保留，不保存
  终端正文或提示词。
- cURL 分析发生在本地 renderer 中，不写日志；分析结果永远不显示完整密钥。cURL 输入框
  在当前项目切换或一键导入成功后清空。已经粘贴到对话、工单或其他第三方位置的密钥仍应
  立即撤销。
- Router 管理凭据只在 Electron 主进程读取并用于本机回环 RPC，不会传给 renderer。
  Provider 列表只显示“是否已配置密钥”。保存 Provider 时只改 CCR 的 `Providers` 和
  `preferredProvider`，不会应用或改写 CCR 中的 Codex profile、Claude profile 或系统代理。
- Router 的 GitHub 安装方式只接受官方仓库当前 Release 中命名匹配的 Windows `.exe`，
  限制最大 250 MiB，并在打开前校验文件大小与 SHA-256。网络受限时可改用 npm 官方源或
  npmmirror；镜像仅作为包下载源，不代替代码签名或供应链审查。
- ClaudeDock 不再通过自身 Electron 可执行文件运行 npm 版 CCR。它会定位 CCR npm 前缀
  旁或 `PATH` 中的系统 `node.exe`，并先验证该运行时可以加载 CCR 自带的
  `better_sqlite3.node`。已被旧版 ClaudeDock 错误启动的服务可由界面定向停止和重启。
- CCR 3.x 的 `preferredProvider` 按 Provider 名称路由。ClaudeDock 同时识别旧配置中遗留的
  Provider ID，并在用户保存该 Provider 时迁移为当前名称，避免以后增加多个 Provider 后
  选错上游。
- 关闭项目会终止该项目的 PowerShell 进程；切换项目不会影响其他项目的运行。
- 「完全允许」（`bypassPermissions`）会让 Claude Code 跳过所有权限确认，风险由用户自行
  承担。ClaudeDock 只在启动时把它加入 `Shift+Tab` 循环，不会替用户进入该模式；工作台的
  开关关闭后，启动命令里不会出现 `--allow-dangerously-skip-permissions`。首次进入时
  Claude Code 自己的一次性免责确认由用户回答，ClaudeDock 不代答。
- 跨端点切换模型和「仅预批准」都需要重启 PowerShell 会话，因为接口地址与凭据是 PTY
  启动时注入的环境变量。重启前的 `/compact` 与重启后的 `--continue` 都是 Claude Code
  自己的官方能力；终端画面会重绘，该终端里原有的其他进程会被终止。
- 底栏模型列表只列出当前配置和该项目的接入历史，凭据不出主进程，列表里只有“是否已配置
  凭据”。被点击的选项在主进程重新核对一遍，模型标识不合法就拒绝写入终端；`/model`
  的斜杠命令白名单没有因此放宽。
- 项目会话只在本次应用运行期间保留，彻底退出后不会恢复终端进程或历史缓冲。
- Claude Code 自己会按项目目录把会话明文保存在 `~/.claude/projects/`，默认约 30 天；
  ClaudeDock 不复制对话正文，只读取标题等元数据和 statusLine 提供的结构化状态。自动命名
  复用 Claude Code 自己根据首条提示词生成并放入 `session_name` 的标题，不另发隐藏提示词；
  用户重命名历史对话时只向对应 UUID JSONL 追加 Claude 兼容的 `custom-title` 记录。删除
  历史对话是不可恢复操作：当前 Claude Code CLI 没有公开的单会话删除命令，因此 ClaudeDock
  使用已有的严格兼容路径，只接受项目路径加合法 UUID 并删除对应 JSONL；绝不调用会清空整个
  项目的 `claude project purge`，也不把这一兼容路径描述为 Claude Code 官方 API。
- 本地构建默认没有代码签名，Windows SmartScreen 可能显示未知发布者提示。
- 当前仅打包 Windows x64。
- 自动发现覆盖 Claude Code Router 的默认 `3456/3458`、LiteLLM 的常用 `4000` 和当前
  项目已保存的本机端口；自定义端口或改名进程可能需要手动填写。
- `@lydell/node-pty` 提供与上游 node-pty API 兼容的按平台预编译包，避免最终用户安装
  Visual Studio C++ 构建组件。

项目面向公开用户使用与评审；维护信息以仓库提交记录和后续发布说明为准。
