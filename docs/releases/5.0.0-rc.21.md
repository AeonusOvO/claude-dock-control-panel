# ClaudeDock 5.0.0-rc.21

发布日期：2026-08-25

## 变更

### 历史记录先选择后确认

- “接入历史记录”初始不再默认恢复任何配置，底部显示灰色“取消”；选中卡片后显示主题化焦点动画、
  勾选标记和“当前选择：XXX”，同尺寸按钮才切换为蓝色“完成”。
- 内联历史、分类弹窗和右键“恢复”全部进入相同确认路径；切换 Claude、ChatGPT、国产模型或 API 分类会
  清空旧选择，避免误确认不可见记录。

### 实测后提交与独立结果页

- 确认后取消普通第一步/第二步展示，改为专用“当前正在接入 XXX”界面。API / 中转站与国产模型会先
  完成真实端点、认证和模型响应测试，全部通过后才提交配置。
- 失败保留逐阶段结果与“重新接入”；成功展示约 1.5 秒后自动回到普通接入页。取消会精确终止当前历史
  事务并等待安全回滚，不会误伤同一项目的其他终端操作。
- 失败或取消会在所有权仍匹配时恢复原项目配置，并精确补偿本次准备写入的 Router 外部状态；检测到用户
  后续保存时拒绝覆盖。跨项目的加载、应用、删除、重命名和恢复结果由 generation + session 双重 fence
  丢弃，旧项目的迟到结果不能污染新项目。
- Claude 官方令牌仍只由 Claude Code 持有，独立 Messages 探针不会读取；账号与登录状态改由主进程执行
  `claude auth status --json` 后按白名单安全投影，命令失败时自然降级且永不暴露令牌。

### 智能当前接入

- 接入页顶部新增“当前接入”摘要。中转站优先显示历史名称，缺失时显示净化后的网址；国产模型显示
  服务商、模型、凭据状态和净化接口；ChatGPT 显示受管网关账号，Claude 显示安全投影的账号、登录状态
  或认证方式，无法可靠获得时明确说明。
- 地址会移除 userinfo、query 和 fragment，界面永不显示 API key 内容；全部组件、焦点、成功/失败状态和
  非线性动效继续由四主题令牌与统一字体层级接管。

## 验证契约

- 完整门禁必须通过 lint、dependency lint、format、三个 tsconfig、全部 Vitest、构建、全量布局场景、
  四主题视觉、控件主题、加速 24 小时 soak 与 `npm run dist`。
- 最终安装包、blockmap 与 `rc.yml` 必须来自同一 exact commit 和 build cohort；COS 先发布不可变资产，
  最后推进 no-cache 的 `rc.yml`。
- 必须从实际安装的 rc.20 使用右上角“检查更新”发现 rc.21；点击“下载并更新”后应完成下载、校验、
  静默安装、自动重启和版本确认。

测试数量、产物大小、SHA-256、cohort 与 Authenticode 状态只取最终候选日志和
`outputs/release-manifest.json`，不在构建前写死。

## GitHub Release 摘要 / Summary

**中文**

本候选版把接入历史改为先选择、再确认、真实连通性测试后提交；新增独立接入结果页、精确取消、失败重试、
跨项目结果隔离、项目与 Router 双重回滚，以及脱敏的“当前接入”摘要，并保持四主题、响应式布局与非线性
动效一致。

**English**

This release candidate changes connection-history replay to select, confirm, test, then commit. It adds a dedicated
recovery result surface, owner-scoped cancellation, retryable failures, cross-project result fencing, project and
Router rollback, and a redacted current-connection summary, while preserving responsive, theme-owned typography and
motion.
