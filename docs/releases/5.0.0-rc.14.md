# ClaudeDock 5.0.0-rc.14

发布日期：2026-08-22

## 网络预检与安全会话

- 工具栏、详情弹层和“网络”设置页的手动检测现在始终立即执行，不再依赖已选服务商、模型、项目或
  活动会话；手动检测一次覆盖 ChatGPT/Codex、Claude、Grok/xAI 官方端点，并同步检查出口、DNS、
  IPv6、分流和时区；Windows 系统首选语言只作参考。
- 应用端点探测改用当前作用域的 Electron `Session.fetch` 和无凭据 `GET`，读取状态与响应头后
  立即停止正文。这修复了 Windows + TUN 下 `ClientRequest` 只发出 `finish -> close`、进而把所有官方端点误报为
  `Network request closed before a response was received` 的问题。manual redirect 的已知官方入口显示为可达警告，
  不跟随未验证目标；精确 API 目标仍 fail-closed。401/403/404/405 只表示官方服务器已经响应。
- 语言来源改为 Windows 的 `getPreferredSystemLanguages()`，不再用应用界面 locale，也不让 CLI 语言覆盖遮蔽系统语言。
  语言与 IP 国家不一致只是参考，不产生风险、不降级证据、不阻止会话，也不再提供语言自动修复。
- IP 风险改为 IPQuery、ProxyCheck 与 Stop Forum Spam 多源对照；分流出口使用独立线路回显交叉检查。
  DNS 不再只看本机配置地址，而是通过 dnscheck.tools 的权威服务器读取实际递归解析出口并与模型出口
  国家对照。关键来源失败、证据缺失或结果冲突时只能显示“不能判断为低风险”。
- 未登录的 WebSocket 探测收到 401/403/426 只表示服务器已响应且需要登录上下文；可选 WebSocket 不再
  把普通 ChatGPT/Codex 连接误写成“云端 WebSocket 功能受限”。只有当前动作明确需要 WebSocket 时才参与阻止。
- 修复 ChatGPT/Codex 或官方 Claude 路由冷启动时“第一次预检失败、手动重测立即成功”的竞态：仅当
  必填失败全部属于 DNS、连接重置、连接失败或超时，且本机仍有活动网络路径时，自动等待 150ms 并
  强制重测一次。离线、TLS、危险跳转、门户网络、CLI 代理不支持和内部错误仍立即阻止。
- Claude 新建/重启会话的阻止结果改为单次决策事务，提供“我再看看 / 重新检查 / 坚持连接”。决策绑定
  精确项目、Provider、配置 revision 和启动 generation，不能跨会话复用；取消同时终止等待与探测。
- “坚持连接”只绕过本次启动，不改全局策略。会话启动后由只读健康监视器定时复查并更新状态；后续
  发现风险也不会擅自停止正在运行的 Claude Code。
- 应用代理保存改为 application / conversation / CLI 三作用域 FIFO 事务，失败逆序恢复；预检以稳定
  epoch 租约读取路由，避免保存代理与首检并发时拿到半新半旧配置。

## Claude Code 执行设置

- 全局设置新增“Claude 执行”选项卡，管理并发子代理、子代理派生深度、工具调用并发和动态工具搜索；
  提供 Claude 默认、五档策略、自定义、“使用推荐”和“恢复 Claude 默认”。改动只作用于未来启动。
- 请求值、Claude 默认值、实际有效值、能力状态、来源和原因分开展示。未知/旧版本保留请求但不注入，
  不把已保存请求伪装成已生效设置。
- 推荐器按逻辑处理器与当前可用内存选择保守基线；没有稳定性基准与额度余量证据时不会自动选择高吞吐
  或最佳性能。更高并发只代表吞吐，不宣称提高模型智能或回答质量。
- Claude Code 2.1.221+ 的官方 Anthropic 路由可直接应用动态工具搜索；自定义/兼容网关必须有精确
  route + model 的新鲜支持证据，避免不支持 `tool_reference` 的代理被误启用。

## 插件、MCP 与交互

- Claude 插件目录建立可追溯来源与推荐策略：官方 Anthropic 市场用精确仓库身份识别，社区与用户市场
  不因名称、远端文案或星数冒充官方；安装、启停、更新与市场管理继续走独立事务。
- MCP 目录接入官方 Registry 的有界 cursor 同步、快照与增量水位；全量同步后再做一次 catch-up，保留
  删除 tombstone，避免分页期间发生的变更丢失。在线失败时保留上一份已验证快照和离线精选。
- 嵌套滚动统一为应用级 child → parent 链：子列表抵达边缘后，剩余滚轮量在同一帧交给祖先；方向反转、
  三层嵌套、弹层封闭和减少动态效果都有行为测试及真实 Electron 验收。
- 无响应的“更多状态 4”替换为可访问的“会话设置” disclosure；窄窗口收纳模型、速度、模式、思考四个
  控件，支持键盘导航、Escape、外部点击与焦点恢复。
- “退出当前账号”改为本地专用退出：只停止 ClaudeDock 托管网关并清除它自己的 OpenAI 授权文件，
  不再复用浏览器 OAuth 换号流程，不操作浏览器、Google 或其他网站登录；重新登录是退出后的独立点击。
- 修复 ChatGPT 托管网关已经加载 OAuth 文件、`GET /v1/models` 已返回 HTTP 200，界面仍在 20 秒后
  误报启动失败的问题：连接归属验证和响应后进程复核不再共用不足的 1.5 秒预算；两步各有
  3 秒执行预算，安全清理与其余网络步骤共同受一次 8 秒 readiness 总预算和 20 秒启动总时限约束。
  最终失败会优先保留脱敏后的最近一次完整预算模型检查类别，清理也失败时组合显示两类脱敏错误，便于区分
  HTTP、响应解析、本机进程身份检查与清理失败。

## 架构

- IPC 扩展为 196 个通道（166 request / 7 send / 23 event），`ControlPanelApi` 同步为 196 个成员；
  preload 共 20 个域桥，主进程共 24 个 IPC 贡献项。
- Claude 启动 handler、受管 ChatGPT 网关、网络预检身份、MCP Registry、下载重试和进程清理继续按域
  拆分；渲染端现为 15 个隔离特性，依赖门禁覆盖 806 个模块且无循环、孤儿或跨层违规。
- 文档同步更新架构、设计、IPC 完整表、项目目录、验证指南与 ADR-0002/0008/0010/0011，并新增
  ADR-0012 记录滚动链与规范遮罩决策。
