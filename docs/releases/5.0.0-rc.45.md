# ClaudeDock 5.0.0-rc.45

发布日期：2026-08-30

## 变更

- 将 Claude 模型连接状态与网络预检、network-security 提示和 router health 分离；成功连接测试或真实模型请求后，独立诊断失败不会再把 footer 降级为连接异常。
- 增加由主进程控制的模型发现与分区选择器，展示当前平台可用模型和历史连接身份使用过的模型；凭据、模型解析、发现和验证仍完全留在主进程，Renderer 只提交短期 opaque option ID。
- 保留完整连接身份和速度配置；同一连接身份内的 footer 切换使用 `/model`，跨连接身份使用受保护的 replay/relaunch，footer 选择不会静默修改未来会话配置。
- 修复模型 context-window suffix 去重、OpenAI 历史 endpoint identity 和订阅模型发现绑定，保持连接历史可恢复性。
- 移除 session-settings 可见 footer 的测量变更，改用离屏测量和合并后的 observer 更新，避免窗口调整时闪烁并保持弹窗焦点状态。
- 持久化剩余配额浮窗的显式显示 / 隐藏选择；`model-usage.json` 继续只保存 accounting journal，不保存账号、凭据、位置或几何信息。
- 加固 Claude Agent SDK 启动、未知阶段处理、初始化清理和 bounded transport recovery；429 与其他瞬时 HTTP 错误遵守有限重试和 `Retry-After`，已有 partial 内容不会被重复 replay。
- 加固 Electron transport 的代理认证、重定向授权、上传和响应取消，以及 conversation native / terminal writer ownership transfer，避免未确认的 writer 并发和悬挂提交。
- 加固下载恢复的 snapshot 校验、启动恢复失败重试、auto-resume 预算、相同 URL 绑定和 task-bound recovery token；恢复确认框竞争改为排队，打开中的确认不会再被解释为用户主动放弃恢复记录。
- 修复 MCP 删除后的项目 toggle 清理，并补充连接、模型发现、配额、下载恢复、对话 ownership、IPC 和 renderer 生命周期回归覆盖。

## 验证门禁

- 最终候选必须在 exact clean commit 上运行完整 `npm run release`，包括 npm ci、lint、format check、三套 typecheck、全量 Vitest、dependency-cruiser、Windows / Electron 相关门禁、NSIS 构建和 release manifest 校验。
- 安装包、blockmap 与 RC 通道清单必须来自同一次最终构建 cohort；产物大小、摘要、源码身份、blockmap 绑定和 Authenticode 状态只从最终 `outputs/release-manifest.json` 记录。
- GitHub Release、腾讯云 COS `rc.yml` 发布、匿名对象复核以及真实客户端“检查更新 → 显式下载并更新 → 安装重启”验收必须分别完成；未完成完整链路前不得标记为用户可更新。
