# ClaudeDock 5.0.0-rc.2

发布日期：2026-08-07

这是 5.0 原生对话候选版的第二轮视觉与交互收敛，不是稳定发布。

## 本轮变化

- “Claude 工作台”和“主题”改用同一个标题栏菜单按钮组件；主题简化为单一按钮打开单一选择卡片，
  窄窗口下两者以相同规则折叠。
- 原生输入坞保留共享提交、附件、键盘与可访问性逻辑，同时按主题呈现不同外壳：Claude 使用柔和
  卡片与圆形上箭头，Telegram 使用紧凑扁平输入条、纸飞机、指针涟漪与飞行动效。
- 当前对话摘要重建为明确四级信息层次；运行中、等待中、已完成改为标题旁标签并使用不同语义色，
  行操作统一放在右侧独立尾列。
- 移除左栏重复的“当前对话状态”卡片，终端错误继续使用按会话代际去重的主题化诊断框；Claude/Codex
  开发引擎选择器改为带图形标识、能力说明、选择勾和主题动效的响应式卡组。
- 修复“项目与对话”在没有外层滚动条时仍永久预留 gutter、导致右边缘比其他组件短一截的问题。
- 去除标题区重复模型/Ultra 说明；状态栏按钮仍保留真实能力和展开说明。
- 修复主题菜单无溢出时仍显示滚动条、发送提示遮挡输入按钮、计划浮层退出残留暗幕和 Telegram
  发送中间帧过度消失的问题；Telegram 输入行与元信息行统一为连续白色表面，不再出现突兀的灰色
  状态栏。

## 视觉验证

- 静态隔离矩阵覆盖四主题、820×640 / 900×640 / 1180×760、125% / 150% / 200% 缩放、摘要、
  主题菜单、附件、计划、诊断、更新和发送动画关键帧。
- 真实隔离 Electron 窗口逐项点击主题菜单、Claude/Telegram 发送、权限、提问、计划、MCP、摘要与
  高级终端；不读取真实项目、会话、凭据，也不启动真实 PTY。

## 发布边界

- Codex 仍使用原生 TUI；5.0 RC 不把实验性 App Server 描述为结构化会话。
- 已生成 `ClaudeDock-Setup-5.0.0-rc.2-x64.exe`、blockmap、`latest.yml` 与 `win-unpacked/`，并确认
  安装包不包含第二份 `claude.exe`。
- 当前本地 RC 安装包的 Authenticode 状态为 `NotSigned`，只可用于内部验证，不能作为正式稳定发布。
