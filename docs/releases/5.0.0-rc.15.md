# ClaudeDock 5.0.0-rc.15

发布日期：2026-08-23

## 应用内更新

- ClaudeDock 应用更新改用腾讯云 COS 的 Electron Builder `generic` feed：
  `https://claudedock-1304375868.cos.ap-shanghai.myqcloud.com/updates/windows/x64/`。
  预发布版本读取 `rc.yml`，稳定版本读取 `latest.yml`，单对象 Range 模式固定为
  `useMultipleRangeRequest: false`。
- `electron-updater` 成为 ClaudeDock 版本检查、下载和安装的唯一权威；原有 GitHub
  `releases/latest` ClaudeDock 检查已移除，GitHub 只保留手动安装包与发布历史用途。
- 首次进入更新中心和手动刷新只检查版本，不自动下载；下载和安装继续分别由用户明确触发。
  已下载更新不会被后台检查覆盖，预发布版本号完整显示，例如
  `v5.0.0-rc.15 → 5.0.0-rc.16`。
- 保留 `autoDownload = false`、`autoInstallOnAppQuit = false`、`allowDowngrade = false`、
  `disableWebInstaller = true` 和 `quitAndInstall(false, true)`。
- rc.14 及更早安装包内嵌的更新源仍指向 GitHub，无法远程改写。本版本是第一版 COS 感知构建，
  既有用户需要手动安装 rc.15 一次；首个完整生产升级证明将使用 rc.15 → rc.16。

## 发布工具

- `npm run release:manifest` 现在按 SemVer 选择 `rc.yml`、`beta.yml` 或 `latest.yml`，并验证
  HTTPS feed、无凭据 URL、单 Range 设置、安装包、blockmap、频道清单、字节数、版本、路径和
  SHA-512 更新链；YAML 使用结构化解析，SemVer 数字标识符不经过 JavaScript `Number`。
- 新增 `npm run release:publish:cos`。发布凭据只从环境变量读取，应用包不包含 COS 凭据、临时签名
  查询或运行期可变更新源；日志和错误会隐藏凭据、授权头、令牌及 URL 查询。
- 安装包和 blockmap 使用 `x-cos-forbid-overwrite: true` 原子创建，只允许相同对象幂等复用；发布器
  拒绝曾启用或暂停版本控制的 bucket，避免版本化对象绕过不可变保证。
- 发布顺序固定为本地验证、不可变对象创建、匿名 HEAD/单字节 Range/完整 SHA-256 与 SHA-512
  复核、频道锁、全部频道预检、频道清单最后写入、公开回读。频道锁包含唯一 owner token，能够恢复
  成功写入但确认响应丢失以及 SDK 重试后返回 409 的情况，删除前重新验证所有权。
- 安装包和 blockmap 使用一年 immutable 缓存；`rc.yml`、`beta.yml`、`latest.yml` 使用强制重新
  验证缓存；发布锁使用 `no-store`。多频道发布仍不是跨对象事务，服务故障后的恢复方式是幂等重跑。

## 完整性边界

- 频道清单中的 SHA-512 证明下载字节与当前读取到的清单一致，HTTPS 保护到 COS 主机的传输。
- 当前安装包为 `NotSigned`，频道清单也没有发布者签名；能够同时替换清单和安装包的写入方不受
  SHA-512 阻止。因此本版本不能描述为具有独立发布者身份认证的正式签名发行版。
