# ClaudeDock 5.0.0-rc.22

发布日期：2026-08-25

## 变更

### 一条对话固定一套完整模型接入

- Claude 终端与原生对话会在创建时绑定平台、协议、接口、认证、订阅账户或 API 凭据身份、Router
  Provider、详细模型与简单模型；恢复历史对话时与当前接入逐项比较，而不再只看一个模型名称。
- 空白简单模型统一按详细模型处理，因此“两个输入都填同一模型”和“简单模型留空”完全等价；真正的
  账户、密钥、路由、接口或任一模型差异仍会被识别。旧对话会从接入历史安全推断，无法完整还原时明确
  说明；同名模型对应多套接入时拒绝猜测账户或 API。

### 可选择、可记忆的恢复弹窗

- 检测到差异时显示背景模糊的原生模态框，左右完整列出对话原接入与正在接入的模型、账户/API、认证、
  协议、脱敏接口和接入名称；“使用当前模型”为蓝色主按钮，原接入为白色次按钮。
- 左下“不再提示”会把本次选择保存为默认；设置的“对话恢复”区域也可随时切回每次询问，或固定使用
  当前/原有接入。另可关闭启动时恢复上次工作区，项目仍保留但不会自动打开最后对话或连接其平台模型。
- 恢复原接入复用真实连接测试与可回滚配置事务。左侧启动按钮显示切换、网络检查和恢复阶段；只有国外
  模型展示网络检查。弹窗、信息卡、方向提示与进度均使用主题化非线性动效并服从 reduced-motion。

### 历史列表与安全边界

- 已由安全终端或原生会话持有的 conversation UUID 不再重复显示在历史区域，避免运行中条目与历史行重叠。
- 恢复所需 API 凭据仅以 Windows `safeStorage` 密文保存；renderer 只接收短指纹和脱敏地址，明文不写入
  偏好文件、IPC、日志或终端命令。OpenAI 上游凭据与本机 Router 客户端凭据分开加密，启动绑定不依赖
  可能缺失或过期的历史记录。

## 验证契约

- 完整门禁必须通过 lint、dependency lint、format、三个 tsconfig、全部 Vitest、构建、全量布局场景、
  四主题视觉、控件主题、加速 24 小时 soak 与 `npm run dist`。
- 必须使用 computer use 操作真实 Electron 窗口，核对标准与窄窗口无重叠、设置保存、差异弹窗双方信息、
  按钮层级、键盘焦点和动效；仅代码或 DOM 样例测试不能替代。
- 最终安装包、blockmap 与 `rc.yml` 必须来自同一 exact commit 和 build cohort；COS 先发布不可变资产，
  最后推进 no-cache 的 `rc.yml`，再从实际安装的 rc.21 完成检查、下载、静默安装、自动重启和 rc.22
  版本确认。

测试数量、产物大小、SHA-256、cohort 与 Authenticode 状态只取最终候选日志和
`outputs/release-manifest.json`，不在构建前写死。

## GitHub Release 摘要 / Summary

**中文**

本候选版让每条 Claude 对话固定完整模型接入身份，新增可记忆的差异选择弹窗、真实测试后恢复原接入、
启动恢复设置、分阶段进度与历史去重，并保持凭据只在主进程加密存储。

**English**

This release candidate binds every Claude conversation to its complete model connection identity. It adds a
rememberable mismatch dialog, tested transactional restoration, startup restore controls, staged progress, and
active-history deduplication while keeping credentials encrypted in the main process.
