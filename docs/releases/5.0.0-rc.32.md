# ClaudeDock 5.0.0-rc.32

发布日期：2026-08-27

## 变更

- 修复最大化窗口下连续新建、恢复或重启对话时，后台终端使用默认行列数解析输出，导致切换后界面
  缩在局部区域的问题。终端从主进程继承实际行列数；同一视口只测量一次，同步到前后台各个终端世代。
- 拒绝迟到的旧尺寸回执，后台终端更换世代也会重新同步视口，不再依赖用户缩小窗口触发重排。
- 网络预检继续让相同目标的并发启动共享进行中的检测；网速、延迟和网络质量估计变化不再误取消
  这些启动。真实联网状态、物理连接类型及代理配置变化仍会使旧检查失效。
- 单个对话的进程清理只核对该对话的所有权，其他对话同时启动或恢复不会让清理失败，也不会覆盖
  其他对话的进程记录。目标对话自身换代仍会拒绝旧扫描结果。
- ChatGPT 托管网关在准备期间不再被状态面板重复探测；相同进程身份与授权文件的并发检查共享
  进行中的操作，授权目录和文件的权限验证合并为一次 Windows 调用。
- 暂时无法检查进程时保留其准确的启动身份，但不授予连接权限；只有明确退出或身份不符才清除记录。
  同时处理模型连接在身份检查期间断开的错误，避免 ECONNRESET 成为主进程未捕获异常。

## 验证门禁

- 回归覆盖后台终端换代、最大化尺寸继承、迟到回执、网络质量事件、跨对话进程清理、网关并发准备、
  暂时不可检查的进程与连接断开。
- 真实 Electron / ConPTY 测试在最大化窗口连续创建十个对话，并发重启全部十一个终端，逐个切换
  核对画布和 PowerShell 实际行列数，再验证窗口尺寸变化与停止、启动、重启生命周期。
- 最终候选通过完整发行编排生成同批 NSIS、blockmap 与 RC 通道清单；交付还需 COS 通道发布、
  远端复核和真实应用内发现、下载、安装及重启验收。实测结果记录在最终候选的验证日志中。

## GitHub Release 摘要 / Summary

**中文**

修复最大化窗口下连续创建与恢复对话的终端显示异常，避免网络质量更新取消共享预检，并减少
ChatGPT 网关与会话进程检查之间的并发冲突。

**English**

Fixes terminal sizing during concurrent conversation creation and restoration in maximized windows.
Network quality updates no longer cancel shared preflight checks. Gateway readiness, authentication
inspection, and session process cleanup now avoid interfering with concurrent conversations.
