# ClaudeDock 5.0.0-rc.41

发布日期：2026-08-28

## 变更

- 修复关闭“每次新建会话时检测”和“每次登录海外服务时检测”后，启动、登录与模型恢复仍自动预检的问题。
  开关现在控制是否探测，而不只是强制刷新缓存或附加环境信息。
- 两项都关闭时，启动、窗口重新显示、网络变化和设置页不再自动预检；新会话检测关闭后，运行中健康
  监测也停止新增探测。保存即影响后续动作，冷启动沿用已保存偏好，设置读取完成前不抢跑。
- 手动“重新检测”保持可用；关闭自动检查不会取消已有登录、会话或终端，不修改实际 HTTPS/TLS 验证，
  不跳过必要的模型连接测试，仍保留代理路由租约、取消与嵌套操作的身份边界。
- 没有结果时明确显示“自动网络预检已关闭”；启动恢复使用“连接验证”文案，关闭前的迟到自动检测
  结果不会重新弹窗、覆盖状态或继续禁用新会话按钮。

## 验证门禁

- 回归覆盖两个开关的独立组合、持久化后重启、保存后生效、登录/启动/切换接入/首个请求、手动检测、
  旧阻止缓存、后台定时器与迟到结果，以及不探测时的路由租约、代理写入、嵌套身份和取消边界。
- 真实 Electron/curl 回环冒烟按服务器收包数验证关闭后的零探测、手动检查与重新开启；支持从最终
  ASAR 加载生产模块复核，不访问真实账户或外部模型服务。
- 最终候选执行全量质量门禁、Windows/Electron 冒烟与加速 soak，再运行完整发行编排生成同批次
  NSIS 安装包、blockmap 和 rc.yml；实测数字与产物事实记录在 exact-commit 日志和最终 manifest。
- 使用隔离测试数据，不为验证开关而重新登录真实账户，不使用 computer-use 操作用户的生产客户端。
  通道发布、下载与实际安装验收分开记录，未执行的生产安装不标记为通过。

## GitHub Release 摘要 / Summary

**中文**

关闭自动网络检测后，启动、登录、恢复模型与后台健康监测真正遵守设置；手动检测和必要的模型连接验证
继续可用。不探测时仍保持代理路由和取消边界，避免旧检测结果继续弹窗或阻止启动。

**English**

Honors the saved automatic network-check preferences during startup, sign-in, connection restoration
and background health monitoring. Manual diagnostics and actual model connection validation remain
available, while route leases, cancellation and stale-result protections remain intact.
