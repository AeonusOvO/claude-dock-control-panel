# ClaudeDock 5.0.0-rc.30

发布日期：2026-08-26

## 变更

- 修复快速连续新建、恢复历史或切换活动对话时，后台启动被全局失效并全部失败的问题；会话启动现在由
  精确 session owner 持有，迟到的工作区快照也不能覆盖更新状态。
- 新建与历史恢复共享设备感知的 FIFO 准入队列。设备阈值内并发启动，超出部分显示实时排队位置；排队
  行的 `×` 直接取消尚未开始的任务，不创建 session，也不出现“关闭并归档”。
- 创建/恢复失败且自动回滚失败的临时行，`×` 直接移除精确临时会话，不再提供无意义的归档选项。
- 启动接入遮罩补充“读取配置、准备接入与网关、网络预检与连接验证、提交接入配置”等当前步骤；Claude
  官方订阅和 ChatGPT 官方订阅显示脱敏后的登录账户，加载箭头按字形方向旋转。
- 设置中的开关明确命名为“启动时自动接入模型”。关闭后会清除全局下个对话接入、跳过自动打开/启动
  历史对话并保持未接入，同时保留项目、历史正文和各对话原有绑定。

## 验证门禁

- 单元回归覆盖设备并发阈值、FIFO、队列取消、失败临时会话关闭、预检决策排队、工作区 revision、启动
  步骤/账户呈现和未接入启动语义。
- 完整门禁必须通过 lint、dependency lint、format、三个 tsconfig、全部 Vitest、构建、布局、控件主题、
  四主题视觉、加速 24 小时 soak 与 `npm run dist`。

## GitHub Release 摘要 / Summary

**中文**

本候选版让工作区新建和历史恢复在设备能力内并发、超限后可见排队，切换前台不再误杀后台启动；同时
完善启动接入步骤、官方账户提示和真正保持未接入的启动设置。

**English**

This release makes workspace creation and history restoration concurrent within a device-aware
limit and visibly queued beyond it, without foreground navigation cancelling background launches.
It also adds truthful startup connection stages, official-account identity, and a real disconnected
startup preference.
