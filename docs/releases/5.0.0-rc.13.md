# ClaudeDock 5.0.0-rc.13

发布日期：2026-08-20

## 架构收敛

- 渲染进程入口 `main.ts` 从 15,886 行的单一作用域收敛为 33 行 shell 入口；14 个特性分片经
  `shell` 编排层与 `platform` 基础设施层、以注册表组合，每个特性按 token + 工厂注册挂载。
- IPC 建立单一事实源：`channels.ts` 的 188 个频道常量（159 request / 7 send / 22 event）与
  `schema.ts` 的逐频道 zod schema；preload 的 19 个桥由同一契约派生，频道名字面量在常量文件之外清零。
- 主进程改为运行期注册表 + 四类贡献点（IPC 域、启动、退出、托盘菜单）装配；新增 IPC 域不再改动装配入口。
- 门禁收紧：ESLint 以 `--max-warnings=0` 运行，任何 warning 即失败；dependency-cruiser 全部规则
  为 error 级。
- 四篇决策记录归档：ADR-0008（IPC 单一事实源）、ADR-0009（行为测试取代源码文本钉，取代 ADR-0003）、
  ADR-0010（主进程注册表与贡献点）、ADR-0011（渲染端注册式分片）。

## 缺陷修复

- 修复应用强制退出后进程树挂起不退出：退出清理正常路径 1 秒级完成，整体由 15 秒预算约束，仍卡住时
  8 秒 watchdog 强制放行。
- 修复运行期会话关闭后 PowerShell 进程滞留：ConPTY 下 node-pty 报告的 PID 不可靠，shell 首条语句改以
  `CLAUDEDOCK_PID` OSC 序列宣告真实 PID，握手成功后按进程树 `taskkill /F /T` 终止。

## 测试基建

- visual 冒烟采样加固；layout 冒烟增加视口就绪轮询，减少时序性假失败。
- 行为测试从源码文本钉全量迁移：渲染端逻辑形态钉清零，改由渲染端、主进程与 IPC 三套 harness 驱动
  可执行的行为断言；用例总数 1096 → 1104。

## 兼容性

- IPC 频道纯增量：本轮仅新增 `app:get-diagnostics`，既有频道与负载不变。
- userData 存储路径零变化，覆盖升级安全。
