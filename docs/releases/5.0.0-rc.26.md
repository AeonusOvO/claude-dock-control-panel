# ClaudeDock 5.0.0-rc.26

发布日期：2026-08-25

## 变更

- 修复新建 Claude 对话时，界面并发读取运行状态会被误判为“运行时已更新”，继而撤销新对话的问题。
- 新建请求现在会在异步网络预检前同步占有稳定的 runtime 身份；状态展示复用同一 owner，真正关闭或替换
  会话仍会让旧启动安全失效。
- ChatGPT 全局准备到第 6 步时明确显示“安装与授权完成；新建或打开对话后即可验证接入”，不再用“正在配置”
  暗示后台仍卡住。
- 未打开对话时，“当前接入”改为“当前没有打开对话”，并说明只有对话打开后才展示实际生效的平台、账号
  和模型，避免把已授权但尚无活动对话误读成接入失败。

## 验证门禁

- 回归测试必须覆盖“启动 baseline → renderer 并发读取状态 → baseline 仍有效”，以及关闭后以相同 session ID
  重建时旧 baseline 必须失效。
- ChatGPT 已授权但没有活动对话时，向导和当前接入摘要必须同时呈现准确的准备/生效边界。
- 完整门禁必须通过 lint、dependency lint、format、三个 tsconfig、全部 Vitest、构建、布局、控件主题、
  四主题视觉、加速 24 小时 soak 与 `npm run dist`。
- 安装包、blockmap 与 `rc.yml` 必须来自同一次最终构建；只有 COS 通道推进并从真实旧版本完成检查、下载、
  安装、自动重启和版本确认后，才能标记为用户可更新。

## GitHub Release 摘要 / Summary

**中文**

本候选版修复 ChatGPT 已授权但新建 Claude 对话会被并发状态读取误取消的问题，并让第 6 步与“当前接入”
准确区分全局安装授权和当前对话实际生效状态。

**English**

This release fixes new Claude conversations being incorrectly cancelled when a concurrent display-state read races
with ChatGPT-backed launch preflight. It also clarifies the boundary between global installation/authorization and the
connection actually active in an opened conversation.
