# ClaudeDock 5.0.0-rc.44

发布日期：2026-08-29

## 变更

- 更新中心打开后立即显示检查状态，并以“待更新”和“历史记录”标签页呈现应用本体、开发工具以及扩展 / 插件的更新；不同来源并行检查，单个来源失败时保留其他来源结果并显示降级原因。
- 为普通下载增加按任务隔离的中断恢复、恢复确认和 discard 清理；只清理对应任务的 journal、`.partial` 与 `.partial.resume`，不误删最终文件或其他任务数据。
- 为应用安装增加独立的恢复记录；安装异常时保留旧版本可启动能力，无法安全续装时明确重新下载并安装。
- 支持将文件拖入 Claude Code 终端、提示词编辑器、footer、workbench 等区域；文件路径在确认后追加到当前提示词草稿，不自动提交，也不直接写入 PTY。文件夹继续走项目添加流程。
- 增加文件拖放确认设置和“不再提示”流程保护；取消或异步导入失败不会关闭后续确认。
- 为 Codex 开发引擎和原生对话高危选项增加随指针定位、键盘焦点、边缘避让、Escape、窗口调整和 reduced-motion 支持的警告提示。
- 区分 Qwen Coding Plan、北京千问普通 API、百炼 / Alibaba Cloud Model Studio 及其他国内模型入口，固定协议、endpoint、credential 类型和使用场景；Coding Plan 与普通 API 不互相替换。
- 为插件目录增加 canonical GitHub Stars 的实时、缓存和内置 fallback；Stars 只参与分类内排序和展示，不改变插件来源、安全级别或安装行为。
- 增加可浏览的 MCP 服务目录和应用自有的 curated install spec；Registry metadata 不能直接生成可执行安装命令，只有审核过的条目可以安装。
- 修复运行中的 Claude 会话切换 GPT Fast / 标准速度后 launch attempt 未接收成功结果的问题，恢复终端、composer、workbench 和输入控件的可用状态。
- 增加 ChatGPT managed subscription 在 Chat API runtime boundary 的强制拦截，并补充文件拖放、下载恢复、provider policy、插件热度、MCP 和生命周期回归覆盖。

## 验证门禁

- 最终候选必须在 exact clean commit 上运行完整 `npm run release`，包括 lint、format check、三套 typecheck、全量 Vitest、dependency-cruiser、Windows / Electron 相关门禁和 NSIS 构建。
- 安装包、blockmap 与当前 RC 通道清单必须来自同一次最终构建 cohort；产物大小、摘要、源码身份和 Authenticode 状态只从最终 `outputs/release-manifest.json` 记录。
- GitHub Release、腾讯云 COS 通道发布、匿名对象复核以及真实客户端“检查更新 → 显式下载并更新 → 安装重启”验收分别记录；未完成完整链路时不得标记为用户可更新。
