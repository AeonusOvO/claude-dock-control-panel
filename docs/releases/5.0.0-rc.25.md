# ClaudeDock 5.0.0-rc.25

发布日期：2026-08-25

## 变更

- 修复启动时“自动连接最近一次选择的平台和模型”在项目配置与最近对话配置相同时误判为已经连接的问题。
- 开关开启时，即使保存的配置没有变化，也会启动所需的本地路由服务、执行真实连接测试并在完成后清理临时会话。
- 开关继续默认开启；用户关闭后，软件启动时不会自动接入平台或模型。
- 设置文案明确区分“保存了模型配置”和“后台服务已经连接”，避免静态配置伪装成可用连接。

## 验证门禁

- 相同配置但后台服务未运行的回归用例必须证明启动事务仍按“打开临时会话 → 连接并验证 → 清理临时会话”执行。
- 模型恢复失败必须关闭临时会话、保留原项目配置并记录可诊断错误，不得留下看似成功的连接状态。
- 完整门禁必须通过 lint、dependency lint、format、三个 tsconfig、全部 Vitest、构建、布局、控件主题、
  四主题视觉、加速 24 小时 soak 与 `npm run dist`。
- 安装包、blockmap 与 `rc.yml` 必须来自同一次最终构建；只有 COS 通道推进并从真实旧版本完成检查、下载、
  静默安装、自动重启和版本确认后，才能标记为用户可更新。

## GitHub Release 摘要 / Summary

**中文**

本候选版修复自动模型连接把“配置相同”误当成“服务已连接”的问题。默认开启时，ClaudeDock 现在会真正
启动最近平台所需的后台服务并验证模型连接；关闭后仍保持启动时不接入。

**English**

This release fixes startup model reconnection treating matching saved configuration as a live connection. With the
default-enabled option, ClaudeDock now starts the required background route and verifies the last platform and model;
when disabled, startup remains disconnected.
