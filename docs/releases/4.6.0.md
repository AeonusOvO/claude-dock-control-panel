## 主要变化

- Claude Code 终端底栏新增按“接入 + 模型”隔离的服务速度菜单，缺省始终为标准速度，不会让一个
  模型或端点的选择串到另一个会话。
- 官方 Anthropic 接入在 Claude Code 2.1.219+ 且模型明确属于 Opus 5 / Opus 4.8 时可请求原生
  Claude Fast。ClaudeDock 不绕过组织资格检查，只有 statusLine 上报 `fast_mode: true` 才显示
  “Claude Fast 已开启”；资格、额度或版本不满足时如实显示未生效或不可用。
- 受管 ChatGPT 的已验证 GPT-5.4/5.5/5.6 系列在 CLIProxyAPI 7.2.117+ 时可向 Claude Code 注入
  `CLAUDE_CODE_EXTRA_BODY={"service_tier":"fast"}`。界面只声明“已请求 GPT 1.5x”，不把请求字段
  冒充为 OpenAI 上游已经采用 priority tier；更高额度消耗和实际计费仍以上游策略为准。
- “小型/备用模型标识”继续代表另一个模型，不再使用容易与服务速度混淆的旧称呼。
  原生 Codex 的速度继续由 Codex 自己管理，本版不修改其启动参数或速度配置。
- 运行中切换速度会用精确 conversation UUID 的 `--resume` 恢复同一对话，不执行 `/compact`；
  PowerShell 重启和命令写入成功后才提交偏好，失败不覆盖原偏好。
- “新建安全会话”“继续最近”“选择历史”现在在点击后的同一事件循环内立即禁用并设置
  `aria-busy`，包括尚无 Claude 状态缓存的冷启动场景。IPC 成功返回不再提前解锁。
- 启动锁按 session 和 generation 隔离，只在观察到新 conversation UUID、新 PowerShell/ConPTY
  PID、Claude 退出回到仍运行的 PowerShell，或明确失败、终端停止/错误、会话删除时释放；旧请求
  的迟到结果不能解锁后来一次启动，也没有不可靠的 renderer 超时。
- 主进程新增 per-session operation coordinator。Claude/Codex 启动、受管 ChatGPT 切换、模型和
  速度重启共享可取消的 PTY 所有权；被取消的旧操作必须先真正 unwind，不能向替代 PowerShell 写入
  迟到命令或回车。开发引擎切换在异步策略检查前后复核活动 agent，终端 `stopped/error` 会同时
  对账 Claude 与 Codex 为 inactive。
- 每次真实 PowerShell/ConPTY spawn 现在拥有独立 `ptyGeneration`。终端输出缓冲、xterm 视图、resize、
  permission probe、启动命令、延迟回车、退出标记和失败清理都必须持有同一 generation；旧 PTY 的
  data/exit callback、RAF、写入完成回调或 `catch/finally` 无法再渲染、写入、停止或清空替代实例。
- 主进程的 8ms / 64KiB UTF-8 字节终端输出合并已提取为 generation-safe batcher：自然退出会在发布
  `stopped/error` 前同步发送该 generation 的末尾缓冲；旧数据与已取消 timer 不能删除新 generation 的
  待发缓冲，flush 前还会复核 live workspace。直接 start/restart/stop 固定按“入口预检
  → 失效旧操作 → 解除精确 probe → 等待 unwind → 再次预检 → generation-scoped 清理 → 同步 PTY
  动作”执行，过期控制请求不会先破坏替代终端再报错。
- renderer 终端输出改用无损、单写入在途的泵：每次 xterm 写入最多 64Ki 个 UTF-16 code unit，
  不切开代理对，只有 callback 确认后才消费队列并推进完整 revision；不再用 512KB 上限丢弃实时输出。
  permission-mode probe 发送前会先 flush 主进程同 generation 缓冲，旧视图回调不能推进替代视图。
- 真实 Windows ConPTY 烟测改为事件驱动：连续执行三轮 restart → stop → start，并验证最终 sentinel
  输出一定先于 `stopped`、停止后无同 generation 迟到数据、旧 generation 不能覆盖最终状态；该烟测
  已加入 production build 后的聚合验证。
- 本机独立对话历史改用同目录唯一临时文件、`wx` 独占写和 `0600` 权限；Windows 重命名只对
  `EACCES` / `EBUSY` / `EPERM` 有界重试，失败不删除上一份有效 `chat-history.json`，清理也不会
  覆盖原始写入/重命名错误。
- 每次 Claude Code launch 使用独立 runtime artifact 目录，同时拥有 `settings.json`、`metrics.json`、
  `signal.json` 与 `turn-stop.json`。所有慢磁盘读取在 I/O 后复核 launch 与 PTY 所有权，旧启动不能消费
  替代会话的信号、覆盖 metrics 或清除新的恢复状态。
- 同一规范化项目目录的开发引擎切换会在第一个 `await` 前保留所有权，并在异步边界后重新枚举全部
  session/generation；项目配置按目录 FIFO 执行“异步准备 → 同步 profile commit → 完成验证/恢复 →
  所有权校验回滚”。OpenAI 转换、历史恢复、Router 保存/修复与放权开关都先取得 session 和目录所有权；
  准备期间原快照保持不变，失败回滚不能覆盖另一会话或外部较新的保存，不同目录仍可并发。CCR Provider
  是先完成的独立持久化，项目 profile 失败只恢复项目快照，不声称撤销已保存的 Provider。
- renderer 的确认、prepare、IPC settlement 与结果应用现在共享 exact-token orchestration；同 PID 的新
  `ptyGeneration` 也会立即释放旧锁，删除 session 会裁剪结果 tombstone。延迟确认、迟到 IPC 拒绝、
  可控 PTY callback 与取消 lease 均有可执行竞态测试，不再只依赖源码形状断言。

## 安全与兼容性

- 现有 Claude Code 安全版本下限不因速度功能提高；不满足 Fast 专用版本或模型条件的会话仍可按
  标准速度启动。未知模型、第三方路由和未验证组合默认不可选 Fast，不做乐观猜测。
- 标准 profile 显式关闭 Claude Fast 并清除继承的 `CLAUDE_CODE_EXTRA_BODY`，避免父进程或前一
  会话把快速服务档位泄漏到其他模型。
- 速度偏好文件只保存去凭据目标的 SHA-256、模式和时间戳，不保存 API Key、OAuth Token、Bearer
  Token 或它们的哈希；文件使用原子写入、权限 `0600`、损坏回退和 400 条裁剪上限。
- Claude Fast 不设置组织检查绕过变量；受管 GPT 的 requested 状态也不使用 Claude
  `fast_mode` 伪造上游确认。
- 本次修改只作用于 ClaudeDock 启动的 Claude Code runtime 和应用内 session 生命周期，不修改
  Codex、Claude Code、CCR、CLIProxyAPI 桌面应用或 Windows 的系统级 API 路由、代理、DNS 和网卡。
- 稳定安装器必须由公开受信任的 Authenticode 主体签署并带可信时间戳。未签名或自签名构建不属于
  4.6.0 正式 Release。
