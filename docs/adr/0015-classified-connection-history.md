# ADR-0015 来源筛选与分类接入历史

- 状态：已采纳
- 日期：2026-08-25

## 背景

项目级接入历史原先把 Claude 官方订阅、ChatGPT 订阅、国产模型和中转站记录放在同一列表。用户再次选择
某一来源时仍需从无关记录中辨认目标，记录较多后信息密度过高。把完整历史只放进设置页又会切断接入主流程，
并形成第二套配置状态。

## 决策

1. 主进程存储、加密、20 条项目上限和现有 IPC 保持不变；renderer 从同一完整列表派生展示，不复制数据。
2. 分类只读取稳定的 provider `preset`：`anthropic`、`chatgpt-subscription`、provider 目录的
   `domestic` 分组、以及兜底的 API / 中转站四类。协议、地址和 Router 运行状态不参与分类。
3. 第二步内联历史只展示当前来源记录。保存、恢复、重命名和删除都先更新完整列表，再重新筛选。
4. 接入页右上角提供完整历史模态入口。四个 panel 常驻同一横向轨道，使用带方向的非线性位移；当前
   模态分类独立于表单来源，避免恢复配置时强制改变浏览位置。
5. 模态使用原生 `<dialog>`、规范主题遮罩和响应式单/双列卡组；非活动 panel 为 `inert`。右键菜单在
   模态打开时进入同一顶层，关闭时还原。

## 后果

- 用户重复接入某一来源时只看到相关配置，同时仍可从一个入口查看完整项目历史。
- 存储格式、敏感字段边界和 IPC 数量不变；分类规则可以用纯函数完整测试。
- 同一历史记录会在内联区或分类弹窗中渲染，但所有操作共享一套 mutation 和 busy 状态。

## 验证

- renderer 单元测试覆盖四类映射、内联筛选、tab 键盘操作、方向位移、顶层右键菜单和焦点恢复。
- Electron 布局烟测在全部支持宽度打开真实历史 dialog，注入长地址与多卡片并检查溢出、裁切和遮挡。
- 视觉烟测保留四主题宽屏图和 820px 单列图，人工核对高斯遮罩、字体层级与主题适配。
