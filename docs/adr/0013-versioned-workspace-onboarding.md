# ADR-0013 版本化工作区启动引导

- 状态：部分被 [ADR-0014](0014-independent-engine-model-access-wizard.md) 取代
- 日期：2026-08-24

## 背景

ClaudeDock 的核心流程已经能自动检测环境、补齐组件、选择路由、发现模型、真实测试并保存，但旧界面
首先暴露项目、Claude Code / Codex 引擎卡、接入、插件与 MCP 等内部概念。新用户需要先理解这些概念
才能进入第一个工作区；升级用户又不能被新的全屏引导打断。

启动引导还跨越 renderer 视图生命周期。若只把 `localStorage` 或 DOM class 当作真值，窗口重载、应用
升级或渲染进程崩溃会丢失进度，也无法可靠区分全新配置与已经使用过的配置。

## 决策

1. 顶层导航固定为工作区、独立对话、接入、扩展；插件与 MCP 只在扩展页内分段。接入与扩展使用完整
   工作画布，工作区仍是默认返回点。
2. 新用户采用四步引导：选择使用路径、自动准备、打开项目、准备完成。未知和项目后才能检测的状态
   必须原样说明，不能为了流程顺滑伪造成功。
3. main 进程的 `OnboardingStore` 是唯一持久化事实源。状态包含 flow version、status、当前步骤、已完成
   步骤、可选路径和更新时间；不存储凭据、模型 ID 或项目正文。
4. 已有偏好、工作区、对话或连接历史构成 legacy-use evidence。没有 onboarding 文件但存在上述证据时
   返回 completed；只有真正的新配置自动打开引导。
5. renderer 的 `onboarding` 特性只持有派生呈现。每次路径或步骤变化通过类型化 IPC 写回；支持跳过、
   续接、完成、重置，以及从设置或空工作区重新打开。
6. 动效必须表达空间关系：打开与关闭共用触发来源原点，前进与返回方向相反，顶层页面只用短促淡化与
   容器变化。全部时长、曲线、表面、字号和字体通过四主题语义令牌；减少动态效果由全局唯一规则接管。

## 后果

- 新用户有一条不要求理解路由内核或模型 ID 的入口；既有用户升级不被遮挡。
- 多出 5 个请求响应频道、1 个 main store、1 个 preload bridge 和 1 个 renderer feature；IPC 总量为
  201，`ControlPanelApi` 也为 201 个成员。
- 引导完成不等同于接入测试完成。它只建立路径和项目范围，真实组件补齐、模型发现与连接测试仍由
  既有项目级自动事务负责。
- legacy evidence 是有意的兼容策略：已经打开过应用但从未完成接入的用户不会被强制引导，仍可从设置
  或空工作区手动重新打开。

## 验证

- store 单元测试覆盖全新、legacy、续接、跳过、重置、完成、非法输入和损坏文件。
- renderer 行为测试覆盖自动打开、路径持久化、前进/返回方向以及从设置收回后返回来源。
- IPC 一致性测试固定 171 request / 7 send / 23 event、201 个频道和 201 个 API 成员。
- 自动门禁后，必须用 Computer Use 在打包后的真实 ClaudeDock 窗口验证导航、四主题、响应式、引导
  往返、键盘焦点与真实工作区状态；测试 fixture 不能代替最终验收。
