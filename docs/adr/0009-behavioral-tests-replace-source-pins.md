# ADR-0009 行为测试替代源码文本钉

- 状态：已采纳（取代 [ADR-0003](0003-source-text-regression-pins.md)）
- 日期：2026-08-19

## 背景

[ADR-0003](0003-source-text-regression-pins.md) 保留约 1,045 处源码文本钉的前提是：渲染进程是单一作用域，没有模块边界，测试无法加载并驱动其中一部分。钉断言的是"代码写成了这个形状"，不是行为；这是当时唯一可行的回归保护。

[ADR-0006](0006-feature-sliced-renderer.md) 的特性分片落地后前提消失。`tests/` 里的断言分两批转换：先在分片期间靠 `source-corpus.ts` 的按目录拼接语料保住命中（ADR-0003 的过渡措施），分片完成后逐类改写为行为测试，最后删除语料设施。

## 决策

钉按性质分四类处理，转换规则如下：

| 钉的类别                                                 | 处理方式           | 替代形态                                                 |
| -------------------------------------------------------- | ------------------ | -------------------------------------------------------- |
| 渲染端逻辑（DOM 更新、状态机、渲染函数）                 | 改写为行为测试     | `renderer-harness` 加载真实模块 + DOM 驱动 + 结果断言    |
| 主进程 store 持久化（JSON 落盘、损坏恢复）               | 改写为黑盒行为测试 | 驱动 store 后读临时目录落盘文件，断言内容                |
| 无法模块加载的资产（CSS token、HTML 结构、组件类名引用） | 保留为资产契约测试 | `design-tokens.test.ts` 经 postcss 解析后断言 token 结构 |
| 测试设施自身需要的文件读取                               | 不算钉             | harness 加载 `index.html` / `styles.css` 构造环境        |

行为测试的基础设施是三个 harness 与两个 fixture：

| 设施                                            | 行数（实测） | 职责                                                                                       |
| ----------------------------------------------- | ------------ | ------------------------------------------------------------------------------------------ |
| `tests/helpers/renderer-harness.ts`             | 377          | jsdom 环境：装载 `index.html`、`styles.css`，注册 `window.controlPanel` 桩，加载渲染端模块 |
| `tests/helpers/main-harness.ts`                 | 430          | 主进程环境：electron mock、`Registry`、`MainState`、深层 stub 依赖容器                     |
| `tests/helpers/ipc-harness.ts`                  | 164          | IPC 往返：捕获 `ipcMain.handle` 注册，驱动 handler 并返回结果                              |
| `tests/helpers/renderer-interaction-fixture.ts` | 134          | 点击、输入、对话框交互的公共夹具                                                           |
| `tests/helpers/renderer-terminal-fixture.ts`    | 291          | 终端会话与 PTY 代际的公共夹具                                                              |

`tests/helpers/source-corpus.ts` 删除——语料拼接的唯一用途是让文本钉在代码搬迁后仍然命中，钉清零后没有存在理由。

## 结果

- 源码文本钉从 1,045 处降到 0 处：对 `src/renderer` 逻辑代码形态的文本断言全部消除。
- `tests/` 共 148 个 `.ts` 文件，`readFileSync` 残留 56 处，分布 27 个文件，全部属于上表的后三类：主进程 store 落盘验证约 50 处（驱动真实 store 后读临时文件断言持久化行为）、设计 token 资产契约 4 处、harness 基础设施 2 处。没有一处读渲染端源码断言代码写法。
- 测试对合法重构免疫：重命名局部变量、改用等价语法不再误报；断言的是模块的可观察行为。
- 用例规模：1,096 个断言全绿（vitest）。
- 代价：行为测试比文本钉运行更慢（jsdom 环境装载、真实 store 落盘），且首次编写成本高——每处转换都要先理解钉背后的原始缺陷。
- 代价：资产契约测试仍然对 CSS/HTML 的字面结构敏感，这是资产文件的固有属性，不随测试方式改变。

## 备选方案

**继续保留全部文本钉，与行为测试并存** —— 1,045 处钉对每次重构都会产生误报噪音，且 ADR-0003 自己已写明"当一段逻辑可以导入并驱动时，就写行为测试，不写文本断言"；并存是拖延而不是方案。

**只转换高风险域，其余钉保留** —— 钉的维护成本与它保护的缺陷数量不成比例；分批转换期间语料设施（`source-corpus.ts`）与 harness 两套设施并存，复杂度最高，尽快收敛到一套。

**用快照测试（snapshot）替代** —— 快照仍然钉住输出的文本形态，对等价重写同样误报，性质上没有离开文本钉。
