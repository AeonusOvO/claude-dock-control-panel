# ADR-0018 全局下个对话接入与不可变会话快照

- 状态：已采纳
- 日期：2026-08-26

## 背景

模型接入曾直接读取活动项目的 Claude 状态，导致没有打开终端时接入页为空、ChatGPT 模型选择被禁用，
项目切换又可能把向导强制送到“配置与验证”。新建会话启动期间如果全局配置变化，后台任务还会读到另一
套端点或因 revision 变化被取消；失败结果则可能留下“正在打开”或已切换下拉框。

## 决策

1. 平台和模型成为应用级“下个对话接入”，与活动项目、终端和“当前接入”解耦。接入页可在零项目状态下
   读取、测试和保存，进入页面始终先显示“选择模型”。
2. `ClaudeConfigStore` 使用 main-only scope 保存完整配置和 DPAPI 密文。三条类型化 IPC 分别读取、真实
   测试和保存；全局写事务 FIFO 串行，并在失败时恢复内部快照和它准备的外部 Router 状态。
3. 新 Claude 终端在 session 分配时同步复制独立 conversation profile；全新原生对话也在 owner 分配时
   复制。后续预检、路由、PTY/SDK 启动和状态读取只消费该快照，下一次选择变化不影响已创建会话。
4. ChatGPT 一键流程在无项目状态下完成环境、安装、OAuth、模型发现、真实测试与保存共 8 步。模型下拉
   使用实时目录并优先推荐现代通用/编码模型；切换失败恢复原选择和原 profile。
5. 启动偏好默认开启。开启时通过短生命周期隔离 session 验证最近对话的完整绑定并提升为下个对话接入；
   关闭时清除全局选择，但保留历史对话绑定和项目数据。
6. renderer 的异步读写拥有精确 generation。迟到读取不能覆盖用户新点击；失败 settlement 同时恢复
   summary、表单、下拉和 disabled 状态，禁止“UI 看似成功，后台实际失败”。

## 后果

- 用户可以先选择平台和模型，再在任意项目中按 `+` 新建对话；两步没有活动终端依赖。
- 同时新建多个对话时，每个会话使用自己点击时捕获的引擎和接入，不因前台切换或后续设置变化而串线。
- 当前对话工作台仍展示和调整它自己的会话快照；普通接入页只描述下一个对话，不暗示热切换现有会话。
- 配置复制增加少量 main-only profile；会话关闭时精确清理，历史正文与恢复记录不依赖这些临时 profile。

## 验证

- main 测试覆盖快速全局保存串行、提交后异常回滚、终端/原生 profile 不可变和凭据密文复制。
- renderer 测试覆盖无项目模型选择、进入接入先回选择页、延迟读取不覆盖点击、ChatGPT 推荐模型及失败回退。
- IPC 契约测试覆盖 212 个频道和 212 个 `ControlPanelApi` 成员。
